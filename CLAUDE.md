# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Boing!" (CMake project name `Boing`) — a small vertical-jumper game in C99 built on [raylib](https://www.raylib.com/). There are **two git submodules** (see `.gitmodules`), so there is no system dependency to install: raylib at `lib/raylib/` (built from source as a CMake subdirectory) and nanosvg at `lib/nanosvg/` (header-only). A plain `git clone` leaves both empty — clone with `--recurse-submodules` or run `git submodule update --init --recursive`.

Gameplay is a [Mega Jump](https://www.halfbrick.com/games/megajump)-style endless climber: collecting coins boosts the player upward, falling below the view kills.

## Design philosophy: homage vs. plagiarism

This game takes inspiration from "Mega Jump" (Halfbrick). Inspiration is fine; copying is not. The rule for all future work — code, art, audio, gameplay, text — is: **everything ships original.** The only third-party code is raylib (with its licensed deps) and nanosvg (zlib, Mikko Mononen — `lib/nanosvg/`, the SVG parser/rasterizer behind the `svg` subsystem). Both are credited in the in-game reel.

**Homage (allowed) — borrow the *genre*, not the *game*:**
- Core mechanic class: endless vertical climb, collect-to-boost, dodge-or-die hazards.
- Generic power-up *concepts* (a magnet that pulls pickups, a rocket that thrusts up) — as long as behaviour, art, and naming are our own.
- Standard arcade structure: menu → play → game over → retry, high score, screen shake juice.

**Plagiarism / infringement (never) — the specifics that identify *their* product:**
- Copying or tracing exact asset designs (their character, coin, monster sprites, logo, fonts).
- Cloning their unique UI layout, screen composition, or menu flow pixel-for-pixel.
- Reusing proprietary names: the title "Mega Jump", named characters, named worlds, named power-ups from their game. Our title and every proper noun must be new.
- Duplicating exact level configurations, spawn tables, or tuning values lifted from their game.
- Copying their music/SFX, or reproducing their audio by ear.

**Rules for future development:**
1. All assets are procedurally generated or authored here from scratch — no ripped/downloaded sprites, fonts, or audio. (The project already does this: procedural chiptune, vector icons authored in this repo, no asset files.) **This covers the SVG sources in `src/svg.c` too** — none are traced or lifted from an icon set (Feather, Lucide, Material, FontAwesome, …); the geometry-heavy ones were generated and the rest hand-authored.
2. Proper nouns (title, characters, power-ups, worlds) are original inventions, not renamed copies.
3. Gameplay values are hand-tuned for *our* feel, not measured from theirs.
4. When in doubt, ask: "does this identify their product, or just the genre?" Genre = fine, product identity = stop.
5. Keep the code comment/README references to "Mega Jump" as *inspiration credit* only — never as a claim of association. The in-game credits reel says "homage only, not affiliated" for the same reason.

## Size limit — 1.44MB (hard constraint)

This project targets the [2PG Arcade 1.44MB contest](https://2pgarcade.com/contest-144mb.html): the final shipped game (executable + runtime + any assets, after decompression) must be **≤ 1,474,560 bytes** — one 3.5" floppy disk. Submission window closes 2026-09-04.

- The default `build/` **is** the shippable build: `CMakeLists.txt` defaults `CMAKE_BUILD_TYPE` to `MinSizeRel` and strips the binary in a POST_BUILD step, so `ls -l build/Boing` is the real shipped size — no separate `build-minsize`.
  ```sh
  ls -l build/Boing
  ```
  As of 2026-07: ~550KB stripped (563,352 bytes), ~890KB headroom. (The `post` subsystem cost 352 bytes: its GLSL is a few KB of `__cstring`, and the rlgl shader entry points it newly references were mostly there already.) The build also link-time dead-strips (`-Wl,-dead_strip` on macOS / `--gc-sections` elsewhere), dropping raylib's unused audio/image/font-format decoders the pure-2D game never calls (~585KB off the pre-dead-strip binary) plus the nanosvg entry points the game never calls.
  - Sizes quantize: `__TEXT` is page-aligned, so a change of a couple of KB often shows **no** size delta at all. Don't read a flat `ls -l` as "my change was free" — check `size -m build/Boing` if it matters.
- Prefer procedural generation (like the existing chiptune) over asset files; every asset counts against the budget. `save.json` is written next to the exe at runtime, so persistence costs nothing against the budget.

## Build & run

```sh
cmake -S . -B build      # configure (first time, or after CMakeLists/new .c files)
cmake --build build      # compile; produces ./build/Boing
./build/Boing            # run
```

- `CMakeLists.txt` globs `src/*.c` (`GLOB_RECURSE`), so **adding or removing a `.c` file requires re-running `cmake -S . -B build`** for it to be picked up.
- **nanosvg** is header-only, pinned as a submodule at `lib/nanosvg/` (headers under `lib/nanosvg/src/`). Its single translation unit is **`lib/nanosvg_impl.c`** — ours, sitting *beside* the submodule rather than inside it, because a submodule is upstream's tree and we don't add files to it. It builds as its own tiny CMake target, deliberately **outside the `src/` glob**, so third-party code never sees our `-Wall -Wextra` or clang-tidy: 4750 lines of it would dominate every rebuild. It still gets `-ffunction-sections -fdata-sections`, so `-dead_strip` drops the parser/rasterizer entry points the game never calls.
- The build defaults to `MinSizeRel` + auto-strip (the 1.44MB budget is the point). Override with `-DCMAKE_BUILD_TYPE=Debug` for a debug build (which also skips the strip step).
- macOS links Cocoa/IOKit/CoreVideo/OpenGL frameworks automatically (`if(APPLE)` block).
- `compile_flags.txt` exists only to feed include paths (`include/`, `lib/raylib/src`, `lib/nanosvg/src`) to clangd/the editor — it is not part of the build.
- **Warnings**: our target compiles with `-Wall -Wextra` (raylib submodule untouched — the flags are on the `Boing` target only). Deliberately *not* `-Wconversion` (the raylib int APIs make float→int narrowing pervasive and it'd flood the build), and `-Wno-unused-const-variable` because `sound.c` keeps a full C0..B8 note-frequency table as a reference (unused pitches are intentional).
- **clang-tidy runs on every build** (LLVM defaults via `.clang-tidy` — `clang-analyzer-*` only, kept minimal because the wider modules flood a raylib game with float↔int narrowing noise; warnings don't fail the build). It's scoped to our target (the `C_CLANG_TIDY` target property), never the submodules. `HeaderFilterRegex: 'include/.*\.h$'` in `.clang-tidy` extends it to our own headers while keeping raylib's and nanosvg's out.
- **clang-format** (LLVM style via `.clang-format`): `cmake --build build --target format` reformats `src/*.c` + `include/*.h` in place. Both tools are gated on being found, so a machine without them still builds.
  - **The tree is format-clean as of 2026-07** (`ba53884`'s follow-up), so the target is now a no-op unless you've actually drifted — run it freely. Keep it that way: it globs *everything*, so if the tree is ever allowed to drift again, one run mid-feature reformats files you never touched and buries the real diff. Check with `clang-format --dry-run -Werror src/*.c include/*.h`.
- No test target is configured. Two self-checks exist, both compiled on demand:
  - `persist`: `cc -DPERSIST_SELFTEST src/persist.c -Iinclude -o /tmp/pt && /tmp/pt` (round-trip + garbage/missing-file asserts).
  - `svg`: renders every glyph to a contact-sheet PNG so the vector art can be eyeballed without launching the game, asserting each one rasterizes non-empty (a typo in path data yields a blank or near-blank cell). Runs headless — no `InitWindow`, since `rasterize()` and `ExportImage` are both CPU-only:
    ```sh
    cc -DSVG_SELFTEST src/svg.c lib/nanosvg_impl.c -Iinclude -Ilib/nanosvg/src \
       -Ilib/raylib/src build/lib/raylib/raylib/libraylib.a -lm \
       -framework Cocoa -framework IOKit -framework CoreVideo -framework OpenGL \
       -o /tmp/svgtest && /tmp/svgtest /tmp/svgsheet.png
    ```
  - `post`: renders a stand-in neon scene through each effect at full strength and writes a 5-cell contact strip, so bloom and fog can be eyeballed without climbing to the neon band or waiting on a Fog drop. Asserts the shader didn't silently fall back to raylib's default program, that the target is supersampled, and that every effect measurably changed the resolved pixels. Needs a GL context (unlike the svg test):
    ```sh
    cc -DPOST_SELFTEST src/post.c -Iinclude -Ilib/raylib/src \
       build/lib/raylib/raylib/libraylib.a -lm \
       -framework Cocoa -framework IOKit -framework CoreVideo -framework OpenGL \
       -o /tmp/posttest && /tmp/posttest /tmp/poststrip.png
    ```

## Layout

Code is header/impl pairs in `include/` + `src/`. Two groups: **screens** (one file per FSM state, all built on the shared `Game` context) and **subsystems** (the reusable engine underneath).

```
src/main.c            loop + STATES[] dispatch table + trackForState
src/game.c            Game context plumbing: transitions, high score, shared button geometry
src/screen_splash.c   SPLASH   — startup logo, drives the audio preload
src/screen_menu.c     MENU     — attract demo, button column, help/missions overlays
src/screen_shop.c     SHOP     — skins + per-power-up upgrade cards
src/screen_credits.c  CREDITS  — CRT zoom-out + scrolling credits reel
src/screen_play.c     PLAYING/PAUSED/GAMEOVER — HUD, pause overlay, run-summary card
src/{theme,player,world,background,sound,ui,svg,post,settings,persist,progress}.c   subsystems
```

## The game loop and FSM

`src/main.c` owns the loop and nothing else. The FSM is explicit: a `Game` context struct (`include/game.h`) threaded through a `STATES[]` dispatch table that maps each `GameState` to `{update, draw}` function pointers — the loop is just `STATES[state].update(&game)` then `.draw`. `GAMESTATE_COUNT` sizes the table and a `STATIC_ASSERT` fails the build if a state has no handler.

States: **SPLASH** → MENU (once, via a black dip), **MENU** ⇄ SETTINGS / SHOP / CREDITS, MENU → **PLAYING** ⇄ **PAUSED**, PLAYING → **GAMEOVER** → PLAYING (retry), pause/game-over HOME → MENU, menu EXIT sets a `quit` flag that ends the loop.

- **Transitions** route through `gotoState`, which records `prevState` — that's how SETTINGS knows which screen to return to (and `drawSettingsState` knows which screen to draw underneath itself). `startTransition(g, next)` instead starts a **black dip**: the loop ramps `fade` to 1, swaps state at the bottom, ramps back. Only the splash→menu handoff uses it today.
- **Physics runs on a fixed 60Hz timestep accumulator** (`screen_play.c`), so gameplay is framerate-independent. `world->hitstop` skips whole steps for impact freeze.
- **Music follows the FSM**: `trackForState` maps UI states to `TRACK_MENU`/`TRACK_GAMEOVER` and gameplay to `themeTrack()`, pushed every frame via `setTrack`.

### Rendering model

Every draw handler works in **fixed 800×800 logical coords**, and the loop wraps the whole frame in an rlgl scale matrix (`rlPushMatrix`/`rlScalef(postScale())`) so it **rasterizes natively at the window resolution** — crisp vectors, no upscaled-texture blur, no letterbox — without touching draw code. `FLAG_WINDOW_HIGHDPI` is set before `InitWindow` so `GetScreenWidth`, the mouse, and `BeginScissorMode` all stay in logical **points**; without it a resized non-HiDPI window reports doubled pixels and the scene overflows.

The frame does not go straight to the window: the loop brackets the draw with `postBegin()`/`postEnd()` (the **post** subsystem), so it lands in a **supersampled offscreen target** that is then resolved through one post-processing shader. Two consequences for draw code: the frame's scale factor comes from `postScale()`, not `GetScreenWidth()/800` (the target is bigger than the window), and anything that escapes the matrix must use that same factor — `screen_credits.c`'s scissor is the only such place. Inside a bound framebuffer `BeginScissorMode` takes its no-DPI-scaling branch and works in raw target pixels, which is exactly what `postScale()` hands it.

**Points vs pixels at the resolve.** The target is sized in **pixels** (`GetRenderWidth()`), but `postEnd` blits it back over a rect in **points** (`GetScreenWidth()`) — not a bug to be "fixed". `EndTextureMode` restores raylib's HiDPI `screenScale` matrix (`lib/raylib/src/rcore.c`), so the backbuffer is back in point space by the time the resolve quad is drawn; matching the two to each other covers a quarter of the window on a 2× display.

In-game the world scrolls under a plain `rlPushMatrix`/`rlTranslatef(-cameraY)` rather than `BeginMode2D`: `BeginMode2D` does an `rlLoadIdentity` and its `EndMode2D` restores raylib's HiDPI `screenScale`, both of which discard the frame's own scale matrix and leave every screen-space draw after it (HUD, pause overlay, game-over) doubled on Retina. HUD/overlays draw after the matching `rlPopMatrix`, back in the frame's scaled 800×800 space.

There are exactly two `RenderTexture`s: post's scene target (above) and `gMenuSnap` — a menu freeze-frame written by the menu screen and zoomed by the CREDITS CRT effect. The menu snapshot is captured in the *update* pass, before `BeginDrawing`, so it never nests inside the post target.

**Icons and glyphs are textures, not primitives.** The `svg` subsystem rasterizes each one once into a mipmapped `Texture2D` and `DrawTexturePro`s it, which sits slightly against the crisp-vector model above: a texture has a fixed pixel size. The mitigation is to rasterize far above the worst-case device size and only ever downsample (mipmaps + trilinear), never upsample — see `SVG_ICON_PX`/`SVG_LOGO_PX` and their sizing arithmetic in `svg.c`. **If a glyph starts drawing much larger than it does today, its raster size has to grow with it** or it will go soft. Everything else on screen is still immediate-mode primitives.

`FLAG_MSAA_4X_HINT` is still set alongside the HiDPI flag, but it is **no longer what antialiases the scene**: a `RenderTexture` can't be multisampled (there is no multisample-FBO path in rlgl), so routing the frame through post's target would have dropped MSAA entirely. Post's 2× supersampling replaces it, and beats it — it also smooths gradient interiors and the point-filtered bitmap font, which MSAA never touched. The flag now only covers the fallback path where post switched itself off. The vector glyphs never depended on either — nanosvg antialiases at raster time.

### Shared context — `game.h` / `game.c`

`Game` holds everything mutable: player, world, settings, progress, high score, the fixed-step accumulator, and the per-screen flags (`showHelp`, `creditsAnim`, `fadePhase`, …). `game.c` holds only what more than one screen needs:

- transitions: `gotoState`, `startTransition`, `returnToMenu`, `startGame(fromMenu)` (fromMenu carries the attract blob straight into play, so PLAY is seamless; retry respawns);
- `loadHighScore`/`saveHighScore` (keys in the shared `save.json`);
- button geometry `centeredBtn` / `centeredRow` and the `drawCoinGlyph` mini-coin;
- `gMenuSnap`, and the SETTINGS bridge (`updateSettingsState`/`drawSettingsState`) that draws the return context underneath the options overlay.

**Button convention**: each button is one `static` rect helper in its own screen file, referenced by `uiButton(rect, …)` in `draw()` and by `clicked(rect)` in the matching `update()` — declared once, used in both. All menus/overlays are fully mouse-playable; keyboard paths run in parallel.

## Screens

- **SPLASH** (`screen_splash.c`) — the gold serif "H" wordmark (`SVG_LOGO`, drawn twice: an offset near-black shadow pass, then the glyph itself) plus a spinning ring loader, on white. Two things preload here — the music and the vector glyphs — so `updateSplash` calls `audioPreloadStep()` **and** `svgPreloadStep()` once per frame (one heavy track bake / one glyph raster each) and leaves for MENU the frame both return true. Both steppers are called unconditionally (no `&&` short-circuit) so neither queue waits on the other to drain. Audio is deliberately silent here (the loop skips `updateAudio` in SPLASH).
  - **The splash is exactly as long as the load — there is no minimum hold and no skip key.** It used to hold a 1.5s arcade beat with the load timer frozen underneath; that is gone, so adding work to a preload queue extends the splash by its own cost and nothing else. ~3.6s today (measured: 3.47s of track bakes, 0.05s of glyph rasters, on an M-series Mac).
  - **Everything expensive belongs in one of those two queues.** `initAudio` bakes nothing, so the window paints its first frame in ~0.08s instead of after a track's worth of prerender; a track with no buffer yet reads as silence in `updateAudio`, which is what makes that safe. The one remaining lazy init is post's shader compile + target alloc on the first `postBegin()` — that lands inside the splash's first frame, before the logo is drawn, and needs no queue. New precomputation goes in a stepper, not in an init function and not on first use.
- **MENU** (`screen_menu.c`) — runs **attract/demo mode** (`updateAttract` wanders the blob); Space/PLAY carries that same blob into gameplay. Buttons: PLAY / SHOP / MISSIONS / SETTINGS / CREDITS / EXIT plus a `?` in the corner. `?` and MISSIONS toggle two **modal read-only overlays** (`showHelp` / `showMissions`) that share one dimmed rounded panel (`overlayPanel`) and one close button (`rOverlayClose`) — while either is open, only the close input is live. The MISSIONS overlay renders the `progress` module's `MISSIONS[]` checklist + rewards against `missionMask`; the help overlay is static `HELP_LINES` text, no interactive walkthrough. Pressing CREDITS snapshots the live menu into `gMenuSnap` before switching.
- **SHOP** (`screen_shop.c`) — the coin economy. A row of skin swatches (buy, click again to equip) over a row of **per-power-up upgrade cards** (`SHOP_PU[]`): each card shows its name, the power-up icon (`drawPowerupGlyph`, reused from `world.c`), then **stacks its 1–3 axes vertically** (`-1` pads the ragged Shield/Debuffs cards). Each axis row is a short label + next-level cost (or MAX) and a **5-segment level bar** (`drawLevelBar` — filled gold segments, not a number); clicking an axis buys the next level. Tables and costs live in `progress`; this file is layout + click routing only.
- **CREDITS** (`screen_credits.c`) — the frozen menu picture **pulls back into a retro CRT set** (`drawCrtCabinet`: wood shell, speaker grille, dials, power LED, rabbit-ear antennae, all scaled by the eased zoom `e`), cuts to a burst of channel **static** (`drawStatic`), then plays a looping **credits reel** (`drawReel` scrolling `REEL_LINES`; lines starting with `-` are pink section headers, blank lines pad the seamless wrap). The tube itself is handed to the `post` pass as `crtRect` — barrel bulge, chromatic split, scanlines and phosphor mask all ramp in with the zoom `e`, replacing the `DrawLine` scanline loop this file used to run every frame. BACK/Esc/Space only responds once fully zoomed out, and reverses the zoom before returning to MENU. Credit text is a homage note only, per the design philosophy above.
- **PLAYING / PAUSED / GAMEOVER** (`screen_play.c`) — one `drawPlay` for all three: background, world under the camera translate, player, power-up aura, then the HUD, then the state-specific overlay (pause button / PAUSED panel / summary card). It also fills the frame's `post` mailbox — bloom from `themeGlow()`, and the Fog debuff, which is now a blur + drifting haze in the post pass rather than the flat dim rect it used to draw here. Fog therefore covers the HUD too; that is deliberate (it's a hazard), and the blur is kept light so the score stays readable. `drawHud` stacks a score badge (top-left), a coin tally right below it (kept off the top-right so the pause button never hides it), a top-center LEVEL progress bar, a `COMBO xN` readout under it (font grows with the combo, shown only while a chain runs), and one timer bar per active power-up. Game over draws `drawSummaryCard`: height / coins / best combo / era reached (`ERA_NAMES`, `STATIC_ASSERT`ed to be one name per `THEMES[]` row) over SCORE/BEST, titled "NEW BEST!" in gold on a record run.

## Subsystems

- **core** (`core.h`, header-only) — `GameState` enum, shared screen constants (`SCREEN_WIDTH`/`SCREEN_HEIGHT`/`FLOOR_Y`), the `clampf` math helper, and `STATIC_ASSERT` (C99 has no `_Static_assert`, so it's the negative-array-size trick). Modules read these instead of taking screen-size parameters.
- **theme** (`theme.h`/`theme.c`) — the palette is **runtime state** (multi-theme). `Theme` is a struct of every scene `Color` (sky/sun/cloud/player/coin/grass/monster/power-up + `confetti[CONFETTI_COUNT]`) plus a `backdrop` style and a `track` id. `THEMES[]` is the table — **four retro-era levels** in climb order: 0 = Sunny Hills (day sidescroller), 1 = Night Blocks (voxel-survival night), 2 = Neon Maze (dot-muncher arcade), 3 = Falling Blocks ("tetris"). Each is a genre homage, never a named product. Adding a level is one more row (plus a `BackdropStyle` case and a `TRACKS[]` row). `THEME_COUNT` is a **macro** so enum-parallel tables elsewhere (`ERA_NAMES`) can be checked at compile time; `theme.c` static-asserts the table actually has that many rows.
  Each frame `themeUpdate(ascent)` recomputes the global `gTheme` by lerping the whole leading run of `Color` fields (via `offsetof(Theme, backdrop)`, itself static-asserted to land on a whole number of `Color`s) between the two neighbor themes over `BAND_HEIGHT` (~20000 units of climb) — so the **whole scene morphs continuously** as you climb. The named `Color` macros (`CANDY_PINK`, `COIN_HI`, `CLOUD`, `GRAPE`, `SKY_TOP`, …) are `#define`d to read `gTheme` fields, so every inline draw site is unchanged. **Static initializers cannot use these macros** (they're runtime lvalues): `POWERUP_DEFS[]` HUD colors and `SKINS[]` palettes use fixed raylib constants / literal `Color`s, and `main.c` calls `themeUpdate(0.0f)` once before `createPlayer`. `themeBlend(&lo,&hi,&f)` exposes the neighbor indices + factor for the background crossfade; `themeGlow()` gives the post-processing bloom weight from a small `GLOW[THEME_COUNT]` table (a separate table, not a `Theme` field, because the struct's leading run must stay all-`Color` for the generic lerp — `STATIC_ASSERT`ed like the rest); `themeTrack()` gives the current music track (it holds the *current* level's track for the whole band, so the music crossfade lands on the level boundary, not mid-band).
- **player** (`player.c`/`.h`) — pure physics + input, knows nothing about the level. `Player` is float `Vector2` position/velocity/acceleration + `radius`, plus a `trail[TRAIL_LEN]` ring buffer. `createPlayer` returns the canonical spawn state (gravity lives in `acceleration.y`); `handlePlayerInput(player, targetX, dir)` reads arrows and, with no arrow held, steers toward `targetX` (the mouse column; a sentinel outside the screen ignores it) — `dir` is `+1` normally and `-1` while Dizzy, flipping arrows and mouse-follow alike; `updatePlayer` integrates, damps, **wraps horizontally** (off one edge → back on the other, shifting the trail by the same delta so it doesn't streak), and pushes the trail; `updateAttract` is the menu demo (wander toward a random target, wrap, bob at the floor line). `drawPlayer` renders a **flat, solid two-tone candy blob** (deliberately un-bubbly — no glow/rim-ring/sheen): motion trail, velocity-driven squash-&-stretch, googly eyes whose pupils lean toward movement + a catch-light each, cheek blush, expression-driven eyebrows, and an expression mouth selected by `player->expression` (`Expression` enum: HAPPY / NEUTRAL / SAD / DIZZY, the last swapping in spiral eyes + a dazed "o"). Blob colors come from the player's `Character`, so a new skin is just a different palette; `createPlayer` stamps the `gSkin` module global (set by `setPlayerSkin`) so the 3 call sites stay arg-free. The attract wander state lives on `Player` — no hidden statics.
- **world** (`world.c`/`.h`) — level content, camera, score. World-space coordinates, up = −y; the camera (`cameraY`, top of view) only moves up, except that it chases a fall up to `DEATH_DROP` past the peak. Fixed pools follow one spawn-above-view / cull-below-view idiom: `Coin` (trail with random-walk x, ~55px apart; **early levels are richer** — while `world->level < COIN_DOUBLE_CAP` each row also drops a bonus coin beside the trail coin), one-way `Platform`s (~300px apart, swept feet check, no tunneling), `Monster`s (~900px bands, drift horizontally; a hit is **not lethal** — it knocks the player down and scatters/costs coins, or, while invincible, splatters the monster), `PowerUp`s (~1500px), and `Particle`s (radial burst, gravity + decay). Three file-scope macros unify the pools: `FIND_FREE`, `FOREACH_ACTIVE`, `CULL`; spawn stays per-type (each pool's logic genuinely differs). Tuning knobs (`COIN_BOOST`, `PLATFORM_BOUNCE`, `SHAKE_*`, …) are `#define`s at the top — game feel is hand-tuned there.
  - **Power-ups are table-driven**: `POWERUP_DEFS[POWERUP_COUNT]` (duration/color/label/spawnWeight/pickupShake/invincible/debuff) indexed by `PowerUpType`, with per-type timers in `powerTimer[]`. A new power-up **or debuff** is a new enum value + one table row (`STATIC_ASSERT`ed complete — a dropped row would divide by zero in the HUD bar). Four good (Magnet, Rocket, Balloon, Shield) and four **debuffs** to dodge (Anchor/heavier gravity, Dizzy/reversed steering, Fog/screen murk, Butterfingers/can't collect coins). Debuffs are just rows with `debuff=true`: `collectPowerups` gives them a SAD face + `SFX_HIT` and no upward boost.
  - **Effects that live outside the table**: `worldInvincible()` reads the `invincible` flag so monster immunity is a query, not a per-type case; `worldInputDir()` (−1 while Dizzy) and `worldFog()` are the parallel queries for the two debuffs whose effect lives elsewhere — Dizzy in `player.c`, Fog in the `post` shader, raised by `screen_play.c`. Shield needs no effect code at all — it's an `invincible=true` row whose `duration` is a **flag** (`1.0f`, skipped by the tick-down) so it persists until monster contacts deplete `world->shieldHits`. Butterfingers is a one-line early-return in `collectCoins`. Dizzy's face is re-forced every frame in `updateWorld` so a coin grabbed mid-spin can't clear it early.
  - **Difficulty ramps with altitude**, keyed on the monotonic `world->level` (capped at `DIFFICULTY_CAP` via the `difficulty()` helper): monsters thicken/speed up/tighten their bands (`GetRandomValue(0,4) <= d`, so 1/5 of bands carry one even at L0), debuffs ramp 0→3/5 (`spawnPowerups` rolls `GetRandomValue(0,4) < d` — strictly-less, so L0 is all good — then `pickPowerup(bad)` weighted-picks within the category), and coins thin from 2-per-row to 1.
  - **Purchased upgrades** hook in via `worldSetUpgrades(const int *puLevel)` — a module global `gPuUpg[]` set per run, indexed by `PuTrack` (mirrors the `gTheme` pattern so `createWorld` callers stay unchanged). Per-level magnitudes are tuning knobs here (`EFFECT_STEP`/`DUR_STEP`/`SPAWN_STEP`), not in the shop table. **Effect** scales magnet radius / rocket thrust / balloon lift (`effectMul`) and seeds Shield's multi-hit charge `1 + level`; **Duration** scales good power-up timers (`durMul`); **Spawn** adds weight in `pickPowerup` (`spawnWeightOf`); **Fewer Debuffs** subtracts its level from the good-vs-bad roll, thinning debuffs to zero once it reaches the altitude level.
  - **Juice**: `updateWorld` owns floor/platform bounce, coin-collect boost, magnet pull, rocket thrust, balloon lift, anchor extra-gravity (placed before the rocket overwrite so rocket still wins), monster hits, decaying `shake` and `flash`, plus the **coin combo** (`world->combo` — each chained coin raises the multiplier and with it pop size, screen shake, and SFX pitch via `sfxPitched`; adds a rising `comboBonus` and tracks `bestCombo`; resets on a floor drop, a monster hit, or a `COMBO_TIMEOUT` idle) and **hit-stop** (a few-frame full physics freeze on monster impact, which `screen_play.c`'s fixed-step loop honours by skipping whole steps). Game over is `isPlayerFallen(...)`; `getScore` = ascent/10 + 5·coins + `comboBonus`.
  - **Drawing** is all cartoon: grassy ground, cloud-pad platforms (`drawCloudPad` draws a **defined solid board** so the jump-off edge reads clearly), minted coins (rim + rotating glint + seed-varied face emblem + out-of-sync sparkle), wobbling grape monsters (drop shadow, rim light, wobbling legs, seed-varied horns/eyes/mouth, angry brows), bobbing power-ups, confetti-fleck particles, and the pop ring. Coins and monsters get deterministic per-instance variety from `entSeed(y)` — a stable hash of the spawn y, no struct fields. `drawPowerUp` is a per-type `switch` (horseshoe magnet, multi-flame rocket, glossy balloon, crested shield, plus four hazard-styled debuff icons), split so the halo/bob-free `drawPowerupGlyph` can be reused by the SHOP cards. Those glyphs are **layered vector art**: each is several theme colors and a texture tint is uniform, so a glyph is one `drawSvg` per color role, back to front (see the `SVG_PU_*` block in `svg.c`). Their shared 24×24 viewBox is scaled so **12 units == `POWERUP_RADIUS`**, which is why every `R * k` in the old primitive code reads as `12 * k` in the path data — keep that mapping when editing them. Three effects stay procedural because they reshape every frame and no fixed picture can stand in: the rocket's flame, the balloon's wavy string, the magnet's blinking spark. `drawPowerAura` orbits one rotating gapped ring per active power-up around the blob at growing radii, in the HUD-matching colors.
- **background** (`background.c`/`.h`) — procedural backdrops, no assets, **theme-aware**. `drawGameBackground(cameraY)` calls `themeUpdate(ascent)`, draws the sky gradient from the blended `gTheme` (so it morphs continuously with altitude), then crossfades the two neighbor themes' backdrop *shapes* — shapes can't lerp, so they alpha-crossfade, and only over the **last ~15% of the band** (`BACKDROP_XFADE_START`) so the next level's decor appears near the boundary instead of bleeding through the whole band. Four backdrop styles share one parallax idiom (`parallaxDepth`/`wrapf`), each dressed with theme-specific detail built from small reusable shape helpers: `drawHillsBackdrop` (rayed sun + drifting gulls + rolling hills topped with trees/bushes + cloud clumps), `drawStarsBackdrop` (moon with craters + twinkling stars + a periodic shooting star + floating grass-topped voxel islands), `drawMazeBackdrop` (scrolling **broken-corridor** neon maze via a per-cell `hash2` + pellets/pulsing power-pellets + drifting ghosts + a chomping hero), `drawBlocksBackdrop` (a faint playfield "well" grid + real falling **tetrominoes** from `TETRO[TETRO_COUNT]` in the theme's confetti colors). `drawMenuBackground` seeds `themeUpdate(0.0f)` (the menu is always level 0) then draws sky + sun + big drifting clouds.
- **sound** (`sound.c`/`.h`) — procedural chiptune **plus procedural SFX**, no sample files, **per-theme**. `TRACKS[]` is the table (`STATIC_ASSERT`ed against the `MusicTrack` ids): each row is a note array + loop `duration` + a `Timbre` (lead voice: warm / soft / pulse / square — bass notes below C3 always fall back to warm so the oom-pah never buzzes) + a `DrumStyle` (baked percussion on a 0.5s beat grid: none / four-on-the-floor / driving) + an `echo` wet mix. Six tracks: four full original level melodies (`NOTES_NATURE` 32s, `NOTES_NIGHT` 32s calm, `NOTES_MAZE` 16s driving chase, `NOTES_ARCADE` 64s), plus menu and game over. **Each track's duration must be a whole number of seconds** so the shared 110Hz A2 tonic-pedal pad has whole cycles at the loop seam.
  `buildLoop(track)` bakes one full loop into `loopBuffer[track]`: notes (`adsr` envelope × `tone` timbre × `accent` downbeat weighting) under the pedal pad, then `bakeDrums` (tails wrap the seam), then `bakeEcho` (two fixed taps read from a dry copy with modulo wrap — seam-safe, no feedback), then peak-normalize (with an `assert(isfinite(peak))` that proves the synth math didn't produce NaN). A failed alloc leaves the slot NULL and the track plays silent. **`initAudio` bakes nothing** — all `TRACK_COUNT` tracks stream in one per frame via `audioPreloadStep()` during the splash, so the heavy prerender never freezes the window (not even the first frame of it). A track whose bake hasn't run yet has `loopSamples 0` and reads as silence.
  `updateAudio` streams 4096-sample chunks with a **per-track `loopPos[]`**. Switching is `setTrack(track)`: it **crossfades (~2s, `FADE_SAMPLES`) only between two level tracks**, and hard-cuts for anything involving menu/game-over, so no music bleeds across a UI boundary. SFX ride the same stream: a fixed 8-voice pool, each effect synthesized per-sample in `renderVoice` (square/sine/saw + decay envelope, a `sweep()` helper, `noise()` for crackle, lengths in `sfxLen[]` — also `STATIC_ASSERT`ed complete), with a **neon variant** (harsher/brighter) selected on the neon levels, summed through a `tanhf` limiter. Public triggers: `sfx(SfxId)` and `sfxPitched(id, pitch)` (the pitch scales sample-time `t`, shifting every frequency uniformly with the duration unchanged — that's the rising coin-combo blip). Music and SFX have **independent levels** (`setVolumes(music, sfx)`, driven by the settings screen) rather than one master volume.
- **ui** (`ui.c`/`.h`) — mouse-driven UI + shared text helpers, no assets. `virtualMouse()` maps window mouse coords (logical points) into the fixed 800×800 draw space so hit-testing matches the scaled draw; `mouseInRect` tests against it and `clicked(rect)` is true on the frame a left-click lands inside. `drawTextShadow`/`drawCenteredText` are the shared shadowed-text helpers used by every screen. `uiButton(rect, label, icon)` draws a rounded cartoon button with hover highlight + optional icon + a label whose font shrinks to fit (draw-only; detect its click with `clicked(rect)`). `drawIcon(kind, …)` draws every icon (`ICON_PLAY`/`PAUSE`/`GEAR`/`RETRY`/`BACK`/`HOME`/`EXIT`/`HEART`/`SHOP`/`MISSIONS`, plus `ICON_NONE`) as a vector glyph via the `svg` subsystem — the body is just an `IconKind` → `SvgId` lookup (`ICON_SVG[]`, indexed `kind - 1` because `ICON_NONE` is the enum's first value and has no row) plus one `drawSvg`. `ICON_SCALE` converts the caller's half-extent `s` into the glyph's box side.
- **settings** (`settings.c`/`.h`) — the options screen reachable from MENU or PAUSED, with **four rows**: framerate, resolution, music volume, SFX volume. Each row is a **horizontal slider**: a generic stop model (`rowStops`/`rowStop`/`setRowStop`) maps every row to discrete stops — one per option for fps/res, 21 (5% steps) for each volume — so the knob snaps. Mouse **drags** the knob (grab band `trackHitRect`, `dragRow` tracks the held row, fraction from `virtualMouse().x`); keyboard ←/→ nudge one stop, ↑/↓ pick the row. The resolution row **defers its `SetWindowSize` until drag release** (`suppressResize` gates the resize inside `applySettings`) so the live window resize can't shift the cursor's slider fraction mid-drag. Values persist as keys in the shared `save.json`; `applySettings` pushes framerate (`SetTargetFPS`), volumes (`setVolumes` — two channels, not `SetMasterVolume`), and resolution (`SetWindowSize`, after which the loop's scale matrix fills the new window). `ROW_LABELS[]` is `STATIC_ASSERT`ed against the `RowKind` enum.
- **svg** (`svg.c`/`.h`) — the vector icon art. Every glyph is an **SVG source string baked into the binary** (no asset files: they'd count against the 1.44MB budget and add a missing-file failure mode), parsed and rasterized once by **nanosvg** into a mipmapped `Texture2D`, then drawn tinted. `SVG_DEFS[SvgId]` is the table — `{src, px}` per glyph, `STATIC_ASSERT`ed complete — and the public surface is just `drawSvg(id, cx, cy, size, rotDeg, tint)`, `svgPreloadStep()` and `unloadSvgCache()`.
  - **Why textures at all**: real curves, real holes, real antialiasing. The old `ICON_GEAR`/`ICON_HOME` faked their holes with a translucent black disc, which only looked right over one background shade; they are now transparent alpha.
  - `drawSvg` fits the viewBox's **larger side** to `size` and centers it, so the draw box is always square whatever the viewBox aspect is, and callers position by center. Content must stay **inside** its viewBox — the rasterizer clips at the box, which is why the rocket's nose and the fog's outer puffs were pulled in from their original offsets.
  - **Colors**: a tint multiplies uniformly, so anything that recolors with the theme is authored **white** and tinted per draw. Multi-color art is therefore split into **one layer per color role** and drawn back to front (the power-up glyphs, the coin's rim/face). Art whose colors are *fixed* can bake them in instead and draw tinted `WHITE` — `SVG_LOGO` carries its own gold gradient that way, and tints near-black for its shadow pass.
  - **Baking** is one glyph per `svgPreloadStep()` call during SPLASH, mirroring `audioPreloadStep()`, so the raster never stalls a gameplay frame. The shared `NSVGrasterizer` is created on the first bake and **released as soon as the queue drains** (and again in `unloadSvgCache`) — it holds scanline buffers sized to the largest raster it has seen, which is the 1024px logo, and nothing needs it once every glyph is resident. A later lazy bake just recreates it. `drawSvg` also lazily bakes on first use as a fallback. A glyph that fails to parse or allocate is marked baked and draws **nothing** — quiet degradation, same contract as a music track whose buffer failed to allocate. `nsvgParse` mutates its input, so sources are copied into a scratch buffer first; one over `SVG_SCRATCH` is skipped rather than truncated (a half SVG parses into garbage shapes).
  - Adding a glyph is one enum value + one table row + the raster size.
- **post** (`post.h`/`post.c`) — post-processing. The whole frame draws into one offscreen `RenderTexture` and resolves through a single GLSL fragment shader whose source is a **string literal baked into the binary** — same no-asset-files doctrine as `svg.c`, and `LoadShaderFromMemory(NULL, src)` supplies raylib's default vertex shader. The public surface is `postBegin()` / `postScale()` / `postEnd(&fx)` / `unloadPost()`, called only from `main.c`'s loop.
  - **Effects are a per-frame mailbox, not a mode**: `PostFx` (bloom / fog / crt / vignette / crtRect) lives on `Game`, `main.c` zeroes it each frame with the always-on vignette pre-raised, and the *drawing screen* raises what it wants — `screen_play.c` sets `bloom = themeGlow()` and the fog ramp, `screen_credits.c` sets `crt` + the tube rect. Each effect is one uniform-gated branch in the shader, so an inactive one is free (a uniform branch is coherent across the whole draw). Adding an effect is one `PostFx` field + one cached uniform loc + one gated block.
  - **The target is supersampled** (`POST_SS`, 2×, dropping to 1× above `POST_SS_MAX` render width so the 1400pt Retina setting doesn't ask for a 5600² target) because it replaces the MSAA a `RenderTexture` can't have — see the Rendering model section.
  - **`GenTextureMipmaps` runs every frame in `postEnd`, unconditionally.** It is tempting to gate it on "does any effect read a mip" — that is a bug: the resolve blit itself minifies (the target is bigger than the window), so the trilinear filter samples mip 1 even with every effect off, and a stale chain shows the frame it was baked on. The chain doubles as bloom's blur (`textureLod` at mips 3/5) and fog's (mip 1.5) — no ping-pong bright-pass target.
  - **Tuning knobs are the `const float`s at the top of the shader string** (barrel, chroma, scanline/triad counts, bloom threshold and gain, fog tint) — the equivalent of `world.c`'s `#define` block. Scanline and triad counts are expressed *per tube*, not per pixel, so the CRT doesn't change density when the window resolution does.
  - **Shader uv is y-down, same as 800-space.** The resolve blit passes a *negative* source height (a framebuffer texture is bottom-up), which lands `fragTexCoord.y = 0` at the top of the window — so `postEnd` normalizes `crtRect` straight by `SCREEN_WIDTH`/`SCREEN_HEIGHT` with no flip, and any new rect-confined effect can do the same. Drop the negative height and every uv-space rect silently flips.
  - **`postScale()` is one scale for both axes**, which is only valid because the logical space is square (800×800) and every `RES_OPTIONS[]` entry in `settings.c` is square too. A non-square resolution option would have to split it into x/y (and the frame's `rlScalef` with it).
  - Two guards that look like paranoia and aren't: an empty `crtRect` zeroes `crt` in `postEnd` (the shader divides by `uRect.zw`), and a shader id equal to `rlGetShaderIdDefault()` counts as a failure, not a success (see quiet degrade below).
  - Quiet degrade: a failed framebuffer or a GLSL error (raylib hands back the *default program* — treated as failure) sets an internal flag and every entry point becomes a no-op, so the game draws straight to the backbuffer exactly as it did before post existed.
  - The credits CRT is confined to `crtRect`. A **global screen warp is skipped by decision**, not left undone: `virtualMouse()` maps raw window coords with no inverse distortion, so warping the whole frame would slide every button off its own art. Adding one means adding the inverse map there first.
- **persist** (`persist.c`/`.h`) — a tiny JSON int key-value store backing a single `save.json` beside the exe (high score + settings + progress all share it). The file is a flat `{"key": int}` object; non-int values (a volume fraction) are stored int-scaled by the caller. `configLoad(path)` parses it into a shared in-memory map once at startup (fixed **24 slots**; a hand-rolled flat-object parser, defensive against a garbage/missing file — the map just stays empty and callers keep their defaults). `configGetInt(key, def)` / `configSetInt(key, val)` read/upsert; `configSave(path)` serializes the whole map. Because every subsystem reads/writes its own keys through the one shared map, the three independent saves **merge** instead of clobbering each other.
- **progress** (`progress.c`/`.h`) — persistent **meta-progression / coin economy** (the "reason to replay"). `Progress` = `{coinBank, skinMask, selectedSkin, missionMask, puLevel[PU_UPGRADE_COUNT]}`, saved through `persist` as the four scalars plus one `pu%d` key per upgrade track (~20 keys). Run coins are scored during a run **and** banked at death (`bankRun`, called from the game-over branch), becoming spendable currency. Three data tables drive the SHOP/MISSIONS screens:
  - `SKINS[]` — original candy palettes, `{Character, cost, name}`, row 0 the free default. A new skin is one row + one `skinMask` bit.
  - `PU_UPGRADES[PU_UPGRADE_COUNT]` — `{label, base}` per upgrade **track**, `cost(level) = base*(level+1)` via `upgCost`. The `PuTrack` enum is the 12 tracks: Magnet/Rocket/Balloon each Spawn/Effect/Duration, Shield Spawn/Effect only (its duration is an until-hit flag), plus one shared `PU_DEBUFF_SUPPRESS`. `MAX_UPG_LEVEL` = 5 buyable levels each, stored in `puLevel[]`. `STATIC_ASSERT`ed complete.
  - `MISSIONS[]` — data-driven `{desc, stat, threshold, reward}` threshold checks (no predicate code), scored once at game over by `bankRun` against one-time `missionMask` bits. Shown read-only in the MENU overlay, **not** in the shop.

  Query helpers: `skinOwned`/`upgLevel`/`missionDone`, `tryBuy` (the single spend guard), `bankRun`. The skin applies via `setPlayerSkin` and the upgrade levels via `worldSetUpgrades` — both **module globals** mirroring the `gTheme` pattern, so constructor call sites stay unchanged. `loadProgress` clamps everything it reads (`save.json` is a user-editable trust boundary). Adding a skin / upgrade track / mission is one table row.

## Robustness convention

Every enum-indexed lookup table carries a `STATIC_ASSERT` tying its size to the enum, so a dropped or added row fails the build instead of silently producing a NULL handler, a zero duration (divide-by-zero), or an out-of-range read: `STATES[]`, `POWERUP_DEFS[]`, `PU_UPGRADES[]`, `TRACKS[]`, `sfxLen[]`, `ROW_LABELS[]`, `THEMES[]`, `ERA_NAMES[]`, `GLOW[]`, `SVG_DEFS[]`, `ICON_SVG[]`, plus the `offsetof(Theme, backdrop)` alignment check that keeps the generic theme lerp valid. Keep this up when adding a table.
