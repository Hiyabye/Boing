# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Boing!" (CMake project name `Boing`) — a small vertical-jumper game in C99 built on [raylib](https://www.raylib.com/). raylib is a **git submodule** pinned at `lib/raylib/` (see `.gitmodules`) and built from source as a CMake subdirectory, so there is no system dependency to install. A plain `git clone` leaves the submodule empty — clone with `--recurse-submodules` or run `git submodule update --init`.

## Design Philosophy: Homage vs. Plagiarism

This game takes inspiration from "Mega Jump" (Halfbrick). Inspiration is fine; copying is not. The rule for all future work — code, art, audio, gameplay, text — is: **everything ships original.** raylib and its licensed deps are the only third-party code.

**Homage (allowed) — borrow the *genre*, not the *game*:**
- Core mechanic class: endless vertical climb, collect-to-boost, dodge-or-die hazards.
- Generic power-up *concepts* (a magnet that pulls pickups, a rocket that thrusts up) — as long as behaviour, art, and naming are our own.
- Standard arcade structure: menu → play → game over → retry, high score, screen shake juice.

**Plagiarism / infringement (never) — the specifics that identify *their* product:**
- Copying or tracing exact asset designs (their character, coin, monster sprites, logo, fonts).
- Cloning their unique UI layout, screen composition, or menu flow pixel-for-pixel.
- Reusing proprietary names: the title "Mega Jump", named characters, named worlds, named power-ups from their game. Our title and every proper noun must be new (see naming brainstorm).
- Duplicating exact level configurations, spawn tables, or tuning values lifted from their game.
- Copying their music/SFX, or reproducing their audio by ear.

**Rules for future development:**
1. All assets are procedurally generated or authored here from scratch — no ripped/downloaded sprites, fonts, or audio. (The project already does this: procedural chiptune, primitive-drawn icons, no asset files.)
2. Proper nouns (title, characters, power-ups, worlds) are original inventions, not renamed copies.
3. Gameplay values are hand-tuned for *our* feel, not measured from theirs.
4. When in doubt, ask: "does this identify their product, or just the genre?" Genre = fine, product identity = stop.
5. Keep the code comment/README references to "Mega Jump" as *inspiration credit* only — never as a claim of association.

## Size limit — 1.44MB (hard constraint)

This project targets the [2PG Arcade 1.44MB contest](https://2pgarcade.com/contest-144mb.html): the final shipped game (executable + runtime + any assets, after decompression) must be **≤ 1,474,560 bytes** — one 3.5" floppy disk. Submission window closes 2026-09-04.

- The default `build/` **is** the shippable build: `CMakeLists.txt` defaults `CMAKE_BUILD_TYPE` to `MinSizeRel` and strips the binary in a POST_BUILD step, so `ls -l build/Boing` is the real shipped size — no separate `build-minsize`.
  ```sh
  ls -l build/Boing
  ```
  As of 2026-07: ~500KB stripped (511,832 bytes), ~945KB headroom. The build
  also link-time dead-strips (`-Wl,-dead_strip` on macOS / `--gc-sections`
  elsewhere, `CMakeLists.txt`), dropping raylib's unused audio/image/font-format
  decoders the pure-2D game never calls (~585KB off the pre-dead-strip binary).
- Prefer procedural generation (like the existing chiptune) over asset files; every asset counts against the budget.

## Build & run

```sh
cmake -S . -B build      # configure (first time, or after CMakeLists/new .c files)
cmake --build build      # compile; produces ./build/Boing
./build/Boing         # run
```

- `CMakeLists.txt` globs `src/*.c` (`GLOB_RECURSE`), so **adding or removing a `.c` file requires re-running `cmake -S . -B build`** for it to be picked up.
- The build defaults to `MinSizeRel` + auto-strip (the 1.44MB budget is the point), so `build/Boing` is already the size-optimized, stripped binary. Override with `-DCMAKE_BUILD_TYPE=Debug` for a debug build.
- macOS links Cocoa/IOKit/CoreVideo/OpenGL frameworks automatically (`if(APPLE)` block).
- `compile_flags.txt` exists only to feed include paths (`include/`, `lib/raylib/src`) to clangd/the editor — it is not part of the build.
- **Warnings**: our target compiles with `-Wall -Wextra` (raylib submodule untouched — the flags are on the `Boing` target only). Deliberately *not* `-Wconversion` (the raylib int APIs make float→int narrowing pervasive and it'd flood the build), and `-Wno-unused-const-variable` because `sound.c` keeps a full C0..B8 note-frequency table as a reference (unused pitches are intentional).
- **clang-tidy runs on every build** (LLVM defaults via `.clang-tidy` — `clang-analyzer-*` only, kept minimal because the wider modules flood a raylib game with float↔int narrowing noise; warnings don't fail the build). It's scoped to our target (the `C_CLANG_TIDY` target property), never the raylib submodule.
- **clang-format** (LLVM style via `.clang-format`): `cmake --build build --target format` reformats `src/*.c` + `include/*.h` in place. Both tools are gated on being found, so a machine without them still builds.
- No test target is configured.

## Layout & architecture

Code lives in `src/` + `include/` as header/impl pairs. `src/main.c` owns the game loop and the `GameState` machine (MENU → PLAYING ⇄ PAUSED, PLAYING → GAMEOVER → PLAYING, plus SETTINGS reachable from MENU or PAUSED, and CREDITS + SHOP reachable from MENU; pause HOME → MENU; menu EXIT sets a `quit` flag that ends the loop). It is an explicit FSM: a `Game` context struct (player/world/settings/highScore/state/…) threaded through a `STATES[]` dispatch table that maps each `GameState` to `{update, draw}` handler function pointers — the loop is just `STATES[state].update(&game)` then `.draw`. Gameplay runs on a **fixed 60Hz timestep accumulator** so physics is framerate-independent; every draw handler works in **fixed 800×800 logical coords**, and the loop wraps the whole frame in an rlgl scale matrix (`rlPushMatrix`/`rlScalef(GetScreenWidth()/800)`) so it **rasterizes natively at the window resolution** (crisp vectors, no upscaled-texture blur, no letterbox) without touching draw code. `FLAG_WINDOW_HIGHDPI` is set before `InitWindow` so `GetScreenWidth`, the mouse, and `BeginScissorMode` all stay in logical **points** and that scale is correct on Retina (otherwise a resized non-HiDPI window reports doubled pixels and the scene overflows). The only remaining `RenderTexture` is `gMenuSnap`, a menu freeze-frame the CREDITS CRT-tube effect zooms (its `BeginScissorMode` rect is pre-scaled by `GetScreenWidth()/800` since the scissor is screen-space, not matrix-transformed). MENU runs **attract/demo mode** (`updateAttract` wanders the blob); Space/PLAY carries the same blob straight into gameplay. MENU also has a `?` button that toggles a static "How to Play" overlay (`showHelp` flag on `Game` + `drawHelpOverlay`/`HELP_LINES` in `main.c`) — plain text, no interactive walkthrough. A **SHOP** button opens the `GAMESTATE_SHOP` screen (`updateShop`/`drawShop` in `main.c`): the coin-economy / progression screen — see the `progress` module below. A **CREDITS** button opens the `GAMESTATE_CREDITS` screen (`updateCredits`/`drawCredits` + `CREDITS_LINES` in `main.c`): static acknowledgements on a dimmed rounded panel (same style as the help overlay), BACK/Esc returns to MENU. Credit text is a homage note only, per the design philosophy above. Gameplay is a [Mega Jump](https://www.halfbrick.com/games/megajump)-style endless climber: collecting coins boosts the player upward, falling below the view kills. Subsystems:

- **core** (`core.h`, header-only) — `GameState` enum, shared screen constants (`SCREEN_WIDTH`/`SCREEN_HEIGHT`/`FLOOR_Y`), and the shared `clampf` math helper. Modules read these instead of taking screen-size parameters.
- **theme** (`theme.h` + `theme.c`) — the palette is **runtime state** now (multi-theme). `Theme` is a struct of every scene `Color` (sky/sun/cloud/player/coin/grass/monster/power-up + a `confetti[6]`) plus a `backdrop` style (`BACKDROP_HILLS`/`BACKDROP_STARS`/`BACKDROP_MAZE`/`BACKDROP_BLOCKS`) and a `track` id. `THEMES[]` in `theme.c` is the table — **four retro-era levels** in climb order: 0 = Sunny Hills (day sidescroller), 1 = Night Blocks (voxel-survival night), 2 = Neon Maze (dot-muncher arcade), 3 = Falling Blocks ("tetris"). Each is a genre homage, never a named product (no proprietary names ship; comments credit inspiration only). Adding a level is one more row. Each frame `themeUpdate(ascent)` recomputes the global `gTheme` by lerping the whole leading run of `Color` fields (via `offsetof(Theme, backdrop)`) between the two neighbor themes over `BAND_HEIGHT` (~20000 units of climb) — so the **whole scene morphs continuously** as you climb. The named `Color` macros (`CANDY_PINK`, `COIN_HI`, `CLOUD`, `GRAPE`, `SKY_TOP`, …) are now `#define`d to read `gTheme` fields, so every existing inline draw site is unchanged. `themeBlend(&lo,&hi,&f)` exposes the neighbor indices + factor for the background crossfade; `themeTrack()` gives the current music/SFX track (holds the current level's track for the whole band, so the music crossfade lands on the level boundary, not mid-band). **Static initializers cannot use these macros anymore** (they're runtime lvalues): `POWERUP_DEFS[]` HUD colors use fixed raylib constants, and `main.c` calls `themeUpdate(0.0f)` once before `createPlayer` so the player copies the Sunny Hills (level 0) palette.
- **player** (`player.c`/`.h`) — pure physics + input, knows nothing about the level. `Player` (float `Vector2` position/velocity/acceleration + `radius`, plus a `trail[TRAIL_LEN]` ring buffer for the motion trail). `createPlayer` returns the canonical spawn state (gravity lives in `acceleration.y`); `handlePlayerInput(player, targetX)` reads arrows and, with no arrow held, steers the blob toward `targetX` (the mouse column; `main.c` passes a sentinel to ignore it); `updatePlayer` integrates, damps, **wraps horizontally** (off one edge → back on the other, shifting the trail by the same delta so it doesn't streak), and pushes the trail; `updateAttract` is the menu demo — wander toward a random target at a steady pace, wrap the edges, bob at the floor line; `drawPlayer` renders a **flat, solid two-tone candy blob** (deliberately un-bubbly — no glow/rim-ring/sheen): motion trail, velocity-driven squash-&-stretch (`DrawEllipse`), googly eyes whose pupils lean toward movement + a glossy catch-light each, cheek blush, expression-driven eyebrows (inner ends tilt with `expression`), and an expression mouth (`DrawRing` smile/frown or `DrawLineEx` neutral) selected by `player->expression` (`Expression` enum — set it on game events for happy/sad reactions). Blob colors come from the player's `Character` (body/bodyDark) so a new character is just a different palette; `createPlayer` stamps the `gSkin` module global (set by `setPlayerSkin` from the selected shop skin — see the `progress` module) so the 3 call sites stay arg-free. The shared trail-write is `pushTrail`, and the attract wander state lives on `Player` (no hidden statics).
- **world** (`world.c`/`.h`) — level content, camera, score. World-space coordinates, up = −y; camera (`cameraY`, top of view) only moves up. Fixed pools all follow the same spawn-above-view / cull-below-view idiom: `Coin` (`MAX_COINS`, trail with random-walk x within `COIN_WANDER`, ~55px apart; **early levels are richer** — while `world->level < COIN_DOUBLE_CAP` each row also drops a bonus coin `COIN_PAIR_GAP` px beside the trail coin, so L0–L1 are 2-per-row and L2+ back to one), one-way `Platform`s (`MAX_PLATFORMS`, ~300px apart, swept feet check, no tunneling), `Monster`s (`MAX_MONSTERS`, ~900px bands, ~1-in-5 chance, drift horizontally; a hit is **not lethal** — it knocks the player down and scatters/costs coins, or, while invincible, splatters the monster), `PowerUp`s (`MAX_POWERUPS`, ~1500px; four good — Magnet, Rocket, Balloon, Shield — plus four **debuffs** to dodge: Anchor/heavier gravity, Dizzy/reversed steering, Fog/screen dim, Butterfingers/can't collect coins), and `Particle`s (`MAX_PARTICLES`, radial burst on coin-collect/bounce, gravity + decay). Power-up behaviour is table-driven: `POWERUP_DEFS[POWERUP_COUNT]` (duration/color/label/spawnWeight/pickupShake/invincible/debuff) indexed by `PowerUpType`, with per-type timers in `powerTimer[POWERUP_COUNT]` — a new power-up **or debuff** is a new enum value + one table row. Debuffs are just rows with `debuff=true`: `collectPowerups` gives them a SAD face + `SFX_HIT` and no upward boost instead of the happy pickup juice. **Debuff frequency ramps with altitude** — `spawnPowerups` first rolls good-vs-bad with `GetRandomValue(0,4) < d` (`d = min(world->level, DIFFICULTY_CAP)` via the `difficulty()` helper), so L0 is all good, L1 1/5 bad, up to L3+ 3/5 bad, then `pickPowerup(bad)` weighted-picks within that category by `spawnWeight`. (This is the strictly-less-than sibling of `spawnMonsters`' `GetRandomValue(0,4) <= d`, which puts a monster on 1/5 of bands even at L0 — powerups stay all-good at L0.) `worldInvincible()` reads the `invincible` flag, so monster immunity is a query, not a per-type special-case; `worldInputDir()` (−1 while Dizzy) and `worldFog()` (Fog timer, drives the `main.c` dim overlay) are the parallel queries for the two debuffs whose effect lives outside `world.c`. Three file-scope macros in `world.c` unify the pools: `FIND_FREE` (first free slot, used by the single-slot spawners), `FOREACH_ACTIVE` (iterate live `.active` slots — used across the update/collect/draw scans), and `CULL` (deactivate below the cull line); spawn stays per-type (each pool's spawn logic genuinely differs). `updateWorld` owns floor/platform bounce, coin-collect boost, magnet pull, rocket thrust, balloon lift (clamps downward velocity to `BALLOON_LIFT`), anchor extra-gravity (`velocity.y += ANCHOR_GRAVITY`, placed before the rocket overwrite so rocket still wins), and monster hits (knockback + coin scatter, all non-lethal), plus decaying `world.shake` (screen shake) and `world.flash` (collect pop-ring); game-over is `isPlayerFallen(...)` (the player fell below the view); `getScore` = ascent/10 + 5·coins + `comboBonus`. **Coin combo juice** (`world->combo`): each coin chained raises the multiplier, and with it the collect pop size, screen shake, and SFX pitch (`sfxPitched`); the chain adds a rising `comboBonus` to the score and tracks `bestCombo` for the game-over card. It resets on a floor-drop, a monster hit, or an idle `COMBO_TIMEOUT` (~2.5s) with no coin (ticked in `updateWorld`). **Hit-stop** (`world->hitstop`): a few-frame full physics freeze on a monster splat/hit — `main.c`'s fixed-step loop skips the whole step (input/physics/spawns) while it counts down, so held shake reads as impact. **Shake tiers** are just per-event magnitudes (`SHAKE_HIT`/`SHAKE_SPLAT`/`SHAKE_LAUNCH` + combo-scaled coin shake). Shield needs no effect code — it's an `invincible=true` def row that `worldInvincible()` picks up; Butterfingers is likewise a one-line guard (early-return in `collectCoins` while its timer runs), Dizzy/Fog do their work in `player.c`/`main.c` via the `worldInputDir`/`worldFog` queries. `drawPowerUp` is a per-type `switch` (real horseshoe magnet with silver pole tips + spark, multi-flame two-tone rocket with fins + shiny porthole, glossy balloon on a wavy string, beveled crested shield, plus the four hazard-styled debuff icons — iron anchor, hypno-swirl goggles, grey mist bank, red-slashed coin — balloon/shield recolor with the theme); `drawWorld` is all cartoon: grassy ground, cloud-pad platforms (`drawCloudPad` draws a **defined solid board** — dark `GRASS_DK` rim + bright top landing face over the cloud-puff backing, so the jump-off edge reads clearly), minted coins (rim + rotating glint + seed-varied face emblem + out-of-sync sparkle), wobbling grape monsters (drop shadow, rim light, wobbling legs, seed-varied horns/antenna/eyes/mouth, angry brows), bobbing/rotating power-ups, confetti-fleck particles (`DrawRectanglePro`), and the pop ring. Coins and monsters get deterministic per-instance variety from `entSeed(y)` — a stable hash of the spawn y, no struct fields. `drawPowerAura(world, player)` (called from `drawPlay` after `drawPlayer`, inside the camera matrix) orbits one rotating gapped `DrawRing` per active power-up around the blob, stacked at growing radii in the HUD-matching `POWERUP_DEFS[].color` — so multiple boosts read as concentric spinning rings. Tuning knobs (`COIN_BOOST`, `PLATFORM_BOUNCE`, `SHAKE_*`, …) are `#define`s at the top of `world.c` — game feel is hand-tuned there. Purchased **permanent upgrades** hook in via `worldSetUpgrades(mask)` (a module global set per run from saved progress): `UPG_HEADSTART` seeds the Shield timer in `createWorld`, `UPG_LONGBOOST` scales good-powerup timers in `collectPowerups`, `UPG_COMBOGRACE` scales the `comboTimer` refresh in `collectCoins` — each a one-line `upg(id)`-gated tweak.
- **background** (`background.c`/`.h`) — procedural backdrops, no assets, **theme-aware**. `drawGameBackground(cameraY)` calls `themeUpdate(ascent)`, draws the sky gradient from the blended `gTheme` (so it morphs with altitude), then `themeBlend(&lo,&hi,&f)` and **crossfades the two neighbor themes' backdrops** — `drawBackdrop(THEMES[lo].backdrop, cameraY, 1-f)` over `drawBackdrop(THEMES[hi].backdrop, cameraY, f)` (shapes can't lerp, so they alpha-crossfade). Four backdrop styles share the same parallax idiom (`parallaxDepth`/`wrapf`), each dressed with theme-specific detail (built from small reusable shape helpers — `drawTree`/`drawBush`/`drawBird`/`drawSunRays`, `drawStar`/`drawMoon`/`drawVoxelIsland`, `drawGhost`/`hash2`, `drawBlockC`/`drawTetromino`/`TETRO`): `drawHillsBackdrop` (rayed sun + drifting gulls + rolling hills topped with trees/bushes + `drawCloud` clumps), `drawStarsBackdrop` (moon with craters + twinkling/sparkling stars + a periodic shooting star + floating grass-topped voxel islands), `drawMazeBackdrop` (scrolling **broken-corridor** neon maze via a per-cell `hash2` + pellets/pulsing power-pellets + drifting arcade ghosts + a chomping hero), and `drawBlocksBackdrop` (a faint playfield "well" grid + real falling **tetrominoes** in the theme's `confetti` colors). `drawMenuBackground` seeds `themeUpdate(0.0f)` (menu is always level 0 / Sunny Hills) then draws sky + sun + big drifting clouds.
- **sound** (`sound.c`/`.h`) — procedural chiptune **plus procedural SFX**, no sample files, **per-theme with crossfade**. Music is now **multi-track**: `TRACKS[]` lists each theme's note array + its loop `duration`, indexed by the `TRACK_L1..L4`/`TRACK_MENU`/`TRACK_GAMEOVER` constants — the four level tracks are `NOTES_NATURE` (L1, 32s), `NOTES_NIGHT` (L2 calm, 32s), `NOTES_MAZE` (L3 driving chase, 16s), `NOTES_ARCADE` (L4, 64s), all full original melodies. `buildLoop(track)` pre-renders **one per-track-length loop** into `loopBuffer[track]` at startup (length from `TRACKS[track].duration`, cached in `loopSamples[track]`; each note gets an `adsr` envelope + `tone` timbre, under a shared A2 tonic-pedal pad tied to the loop length, peak-normalized; a failed alloc leaves the slot NULL and plays silent). Each track's duration must give the 110Hz A2 pedal whole cycles (integer seconds) for a seamless seam. `updateAudio` streams 4096-sample chunks with a **per-track `loopPos[]`** (each wraps at its own `loopSamples`), **crossfading** `curTrack`/`prevTrack` by a `fade` gain (~2s, `FADE_SAMPLES`); `setTrack(track)` starts a fade (no-op if unchanged), driven each frame from `main.c` via `setTrack(themeTrack())`. SFX ride the same stream: a fixed `voices[MAX_VOICES]` pool, each effect synthesized per-sample in `renderVoice` (square/sine/saw + decay envelope, a `sweep()` helper for the pitch-fall voices, lengths in `sfxLen[]`) with a **neon variant** (harsher/brighter) selected on the neon levels (`curTrack == TRACK_L3 || TRACK_L4`), summed through a `tanhf` limiter. One public trigger `sfx(SfxId)` (`SFX_COIN`/`BOUNCE`/`POWERUP`/`HIT`/`SELECT`/`LEVELUP`/`GAMEOVER`/`SPLAT`/`PICKUP`/`NEWBEST`), plus `sfxPitched(id, pitch)` — the pitch scales the sample-time `t` in `renderVoice`, shifting every frequency uniformly with the duration unchanged (drives the rising coin-combo blip); `world.c` fires the gameplay ones (`SFX_SPLAT` on an invincible plow-through, `SFX_PICKUP` on Balloon/Shield pickup), `main.c` fires `SFX_GAMEOVER` on an ordinary death and `SFX_NEWBEST` (a dedicated grand ascending fanfare, not the level-up) on a new high score, `main.c`/`settings.c` fire `SFX_SELECT`.
- **ui** (`ui.c`/`.h`) — mouse-driven UI + shared text helpers, no assets. `virtualMouse()` maps window mouse coords (logical points) into the fixed 800×800 draw space (uniform scale, no letterbox) so all hit-testing matches the scaled draw; `mouseInRect` tests against it and `clicked(rect)` is true on the frame a left-click lands inside it. `drawTextShadow`/`drawCenteredText` are the shared shadowed-text helpers used by every screen. `uiButton(rect, label, icon)` draws a rounded cartoon button with hover highlight + optional shape icon + label (draw-only; detect its click with `clicked(rect)` in the matching update handler). `drawIcon(kind, …)` builds every icon (`ICON_PLAY`/`PAUSE`/`GEAR`/`RETRY`/`BACK`/`HOME`/`EXIT`/`HEART`) (`ICON_PLAY`/`PAUSE`/`GEAR`/`RETRY`/`BACK`/`HOME`/`EXIT`/`HEART`/`SHOP`) from raylib primitives only (`DrawTriangle`/`DrawRing`/`DrawRectanglePro`/`DrawCircle`/`DrawLineEx`/`DrawEllipse`). Convention: each button is one `static` rect helper in `main.c`/`settings.c`, referenced by `uiButton(...)` in draw() and `clicked(...)` in update(). All menus/overlays are fully mouse-playable; keyboard paths stay in parallel.
- **settings** (`settings.c`/`.h`) — the options screen (framerate/resolution/volume) reachable from MENU or PAUSED. Each row is a **horizontal slider**: a generic stop model (`rowStops`/`rowStop`/`setRowStop`) maps every row to discrete stops — one per option for fps/res, 21 (5% steps) for volume — so the knob snaps to the nearest stop. Mouse **drags** the knob (grab band `trackHitRect`, `dragRow` tracks the held row, fraction from `virtualMouse().x`); keyboard ←/→ nudge one stop via `changeRow`, ↑/↓ pick the row. The resolution row **defers its `SetWindowSize` until drag release** (`suppressResize` flag gates the resize inside `applySettings`) so the live window resize can't shift the cursor's slider fraction mid-drag. Values persist to a plain-text `settings` file beside the exe (runtime-generated, doesn't count against the budget); `applySettings` applies framerate (`SetTargetFPS`), volume (`SetMasterVolume`), and resolution (`SetWindowSize`, then the loop's scale matrix fills the new window).
- **persist** (`persist.c`/`.h`) — shared plain-text int-record I/O for the runtime files beside the exe. `readInts(path, buf, n)` / `writeInts(path, buf, n)` back the `highscore` (1 int), `settings` (4 ints; volumes stored as int percents), and `progress` (5 ints) files, replacing the copied fopen/fscanf skeletons. `readInts` returns false and leaves `buf` untouched on a missing/garbage file, so callers keep their defaults.
- **progress** (`progress.c`/`.h`) — persistent **meta-progression / coin economy** (the "reason to replay"). `Progress` = `{coinBank, skinMask, selectedSkin, upgradeMask, missionMask}`, saved as 5 ints in a `progress` file via `persist` (runtime-generated, off the budget). Run coins are still scored during a run **and** banked at death (`bankRun` in the `main.c` game-over branch), becoming spendable currency. Three data tables drive the SHOP screen: `SKINS[]` (original candy palettes — `{Character, cost, name}`, row 0 the free default; a new skin is one row + one `skinMask` bit), `UPGRADES[]` (one-time permanent unlocks, bit index into `upgradeMask`: `UPG_HEADSTART` = open each run shielded, `UPG_LONGBOOST` = +50% good-powerup duration, `UPG_COMBOGRACE` = +50% combo timeout), and `MISSIONS[]` (data-driven `{desc, stat, threshold, reward}` threshold checks — no predicate code — scored once at game over by `bankRun`, one-time `missionMask` bits). Query helpers: `skinOwned`/`upgradeOwned`, `tryBuy` (central spend guard), `bankRun`. The skin applies via `setPlayerSkin` (player module); the upgrades apply via `worldSetUpgrades` (world module) — both **module globals** mirroring the `gTheme` pattern so `createPlayer`/`createWorld` callers stay unchanged. Adding a skin/upgrade/mission is one table row.

In-game drawing scrolls the world with a plain `rlPushMatrix`/`rlTranslatef(-cameraY)` (the camera is a pure translation — zoom 1, no rotation) rather than `BeginMode2D`: `BeginMode2D` does an `rlLoadIdentity` and its `EndMode2D` restores raylib's HiDPI `screenScale`, both of which discard the frame's own scale matrix and leave every screen-space draw after it (HUD, pause overlay, game-over) doubled on Retina. HUD/overlays draw after the matching `rlPopMatrix`, back in the frame's scaled 800×800 space. `drawHud` stacks a score badge (top-left), a coin tally right below it (a mini coin glyph + count, kept off the top-right so the pause button never hides it), a top-center LEVEL progress bar, a `COMBO xN` readout under it (only while a chain runs, font grows with the combo), and one timer bar per active power-up. Game over draws a **run-summary card** (`drawSummaryCard` in `main.c`): a bordered panel with height/coins/best-combo/era-reached (era name from `ERA_NAMES[worldLevel%4]`) over the SCORE/BEST lines.

Built since: procedural SFX (coin/bounce/powerup/hit/select + level-up, game-over, splat, a Balloon/Shield pickup variant, and a dedicated new-best fanfare), a stacking power-up aura on the player (`drawPowerAura`) + a gold "NEW BEST!" title replacing "GAME OVER" on a record run, monsters (non-lethal: `updateMonsters` knocks the player down and costs coins, or splatters the monster while invincible), power-ups (Magnet, Rocket, Balloon, Shield) + debuffs to dodge (Anchor, Dizzy, Fog, Butterfingers) — all table-driven via `POWERUP_DEFS[]`, a CREDITS screen (FSM state off the menu), particle bursts (`spawnParticles`/`updateParticles`), high-score persistence (via the `persist` module, plain text `highscore` file beside the exe — runtime-generated, doesn't count against the 1.44MB budget), and a full bright-cartoon aesthetic pass (shared `theme.h` palette, googly-blob player, cloud/sky backgrounds, confetti + screen shake juice, warm arranged audio, shadowed HUD with score badge + coin tally + power-up timer bar), a **juice pass** (coin combo → rising multiplier/pitch/pops, hit-stop on monster impacts, per-event shake tiers, game-over run-summary card), a **settings screen** (framerate/resolution/volume as draggable sliders, persisted to a `settings` text file), **native-resolution rendering** (rlgl scale matrix + `FLAG_WINDOW_HIGHDPI`, no upscaled-texture blur), **framerate-independent physics** (fixed-timestep accumulator), **full mouse support** (the `ui` module — shape-icon buttons, mouse-follow steering), **horizontal screen-wrap**, **attract/demo mode** on the menu, and an **explicit FSM** (`Game` struct + `STATES[]` dispatch table; transitions route through `gotoState`, which records `prevState` so SETTINGS returns to whichever screen opened it).

Multi-theme scaffolding: the palette is runtime (`Theme`/`THEMES[]`/`gTheme`), the scene morphs continuously across **four retro-era levels** (Sunny Hills → Night Blocks → Neon Maze → Falling Blocks, then loops) over `BAND_HEIGHT` (~20000 units) of climb each. Backdrops alpha-crossfade (hills→stars→maze→blocks), and music/SFX crossfade per theme (`TRACKS[]`, `setTrack`); the four level tracks are full original melodies. Each level homages a *genre/era*, never a named product. Adding a fifth theme = one `THEMES[]` row (+ a new `BackdropStyle` case in `background.c` if it needs a new shape, + a `TRACKS[]` row + `MusicTrack` id for its music).

Altitude-scaled difficulty is built and keyed on the monotonic `world->level` (`DIFFICULTY_CAP`): monsters thicken/speed up/tighten their bands, debuffs ramp 0→3/5, and coins thin from 2-per-row to 1 (`COIN_DOUBLE_CAP`).

Multiple characters ship as coin-unlocked **skins** (the `progress` module's `SKINS[]` + SHOP screen).
