# AGENTS.md

This file provides guidance to coding agents working in this repository.

## What this is

"Boing!" (CMake project name `Boing`) is a small macOS-only vertical-jumper game in C99 built on [raylib](https://www.raylib.com/). The default artifact is one Universal 2 `Boing.app` for Apple Silicon and Intel, with macOS 11.0 as its deployment target. There are **two git submodules** (see `.gitmodules`), so users have no dependency to install: raylib at `lib/raylib/` (built statically from source as a CMake subdirectory) and nanosvg at `lib/nanosvg/` (header-only and linked statically). A plain `git clone` leaves both empty; clone with `--recurse-submodules` or run `git submodule update --init --recursive`.

Gameplay is a [Mega Jump](https://www.halfbrick.com/games/megajump)-style endless climber: collecting coins boosts the player upward, falling below the view kills. Each of the five era bands then changes a **rule**, not just the palette — see `worldEra()` under the **world** subsystem.

## Design philosophy: homage vs. plagiarism

This game takes inspiration from "Mega Jump" (Halfbrick). Inspiration is fine; copying is not. The rule for all future work — code, art, audio, gameplay, text — is: **everything ships original.** The only third-party code is raylib (with its licensed deps) and nanosvg (zlib, Mikko Mononen — `lib/nanosvg/`, the SVG parser/rasterizer behind the `svg` subsystem). Both are credited in the in-game reel.

**Homage (allowed) — borrow the *genre*, not the *game*:**
- Core mechanic class: endless vertical climb, collect-to-boost, dodge-or-die hazards.
- Generic power-up *concepts* (a magnet that pulls pickups, a rocket that thrusts up) — as long as behaviour, art, and naming are our own.
- Standard arcade structure: menu → play → game over → retry, high score, screen shake juice.

**Plagiarism / infringement (never) — the specifics that identify *their* product:**
- Copying or tracing exact asset designs (their character, coin, monster sprites, logo, fonts).
- Cloning their unique UI layout, screen composition, or menu flow pixel-for-pixel.
- Reusing proprietary names: the title "Mega Jump", named characters, named worlds, named power-ups from their game. Our title and every proper noun must be new.
- Duplicating exact level configurations, spawn tables, or tuning values lifted from their game.
- Copying their music/SFX, or reproducing their audio by ear.

**Rules for future development:**
1. All assets are procedurally generated or authored here from scratch - no ripped/downloaded sprites, fonts, or audio. The in-game art remains generated or embedded as original vector source; `resources/BoingIcon.svg` and its compact `Boing.icns` are the sole file assets, required by Finder and Dock. **This covers the SVG sources in `src/svg.c` too** - none are traced or lifted from an icon set (Feather, Lucide, Material, FontAwesome, ...); the geometry-heavy ones were generated and the rest hand-authored.
2. Proper nouns (title, characters, power-ups, worlds) are original inventions, not renamed copies.
3. Gameplay values are hand-tuned for *our* feel, not measured from theirs.
4. When in doubt, ask: "does this identify their product, or just the genre?" Genre = fine, product identity = stop.
5. Keep the code comment/README references to "Mega Jump" as *inspiration credit* only — never as a claim of association. The in-game credits reel says "homage only, not affiliated" for the same reason.

## Size limit — 1.44MB (hard constraint)

This project targets the [2PG Arcade 1.44MB contest](https://2pgarcade.com/contest-144mb.html): the final shipped game (executable + runtime + any assets, after decompression) must be **≤ 1,474,560 bytes** — one 3.5" floppy disk. Submission window closes 2026-09-04.

- The default `build/` **is** the shippable build: `CMakeLists.txt` fixes both `arm64;x86_64` slices and a macOS 11.0 deployment target, defaults to `MinSizeRel`, strips the executable, copies the original app icon and three license files, and seals `build/Boing.app` with a Hardened Runtime ad-hoc signature. A post-build CMake script sums every file in the decompressed bundle and fails over the contest limit.
  ```sh
  find build/Boing.app -type f -exec stat -f %z {} \; | \
    awk '{ total += $1 } END { print total }'
  ```
  Current bundle: 1,372,531 bytes, 102,029 bytes headroom. The 1,285,408-byte executable contains both CPU slices; `resources/Boing.icns` costs 80,247 bytes and the Info.plist, licenses, and ad-hoc signature make up the rest. The linker still dead-strips unused functions/data from our code and the two static dependencies.
  - Sizes quantize: each architecture has page-aligned Mach-O segments, so a small source change can move the universal executable by tens of KB. Measure the whole `.app`, not only `Contents/MacOS/Boing`.
  - Bundle resources are copied by an explicit `PRE_LINK` command. Do not move them back to `MACOSX_PACKAGE_LOCATION`: with Unix Makefiles those generated copies run after target `POST_BUILD` commands, causing signing and the size guard to validate an incomplete app.
  - `Boing.icns` deliberately carries one recompressed 1024px `ic10` representation. A conventional ten-image iconset was 627,809 bytes and broke the budget; the single scalable representation is 80,247 bytes and macOS 11 supports it. Keep `BoingIcon.svg` as the authored source and do not regenerate a full iconset without rechecking the bundle.
- Prefer procedural generation like the existing chiptune over additional assets; every bundled file counts. The runtime save lives at `~/Library/Application Support/Boing/save.json`, outside the signed app and outside the submission budget.

## Build & run

```sh
cmake -S . -B build      # configure (first time, or after CMakeLists/new .c files)
cmake --build build      # compile; produces ./build/Boing.app
open build/Boing.app     # run through Launch Services, like an end user
```

- `CMakeLists.txt` globs `src/*.c` (`GLOB_RECURSE`), so **adding or removing a `.c` file requires re-running `cmake -S . -B build`** for it to be picked up.
- **nanosvg** is header-only, pinned as a submodule at `lib/nanosvg/` (headers under `lib/nanosvg/src/`). Its single translation unit is **`lib/nanosvg_impl.c`** — ours, sitting *beside* the submodule rather than inside it, because a submodule is upstream's tree and we don't add files to it. It builds as its own tiny CMake target, deliberately **outside the `src/` glob**, so third-party code never sees our `-Wall -Wextra` or clang-tidy: 4750 lines of it would dominate every rebuild. It still gets `-ffunction-sections -fdata-sections`, so `-dead_strip` drops the parser/rasterizer entry points the game never calls.
- The build defaults to `MinSizeRel` + auto-strip (the 1.44MB budget is the point). Override with `-DCMAKE_BUILD_TYPE=Debug` for a debug build (which also skips the strip step).
- macOS is the only supported platform. Cocoa/IOKit/CoreVideo/OpenGL are Apple system frameworks and are intentionally not copied into the bundle. `otool -L build/Boing.app/Contents/MacOS/Boing` must show only `/System/Library` and `/usr/lib` dependencies; raylib, GLFW, and nanosvg are static.
- Every normal build gets a Hardened Runtime ad-hoc signature for local integrity and release-mode compatibility testing only. It is not Gatekeeper-trusted and cannot be notarized. A paid Apple Developer Program membership and `Developer ID Application` certificate are required to replace it with a Hardened Runtime + timestamp signature, submit a zip with `notarytool`, and staple the ticket. The exact release sequence is in `README.md`; rebuilding afterward restores the ad-hoc signature.
- `compile_flags.txt` exists only to feed include paths (`include/`, `lib/raylib/src`, `lib/nanosvg/src`) to clangd/the editor — it is not part of the build.
- **Warnings**: our target compiles with `-Wall -Wextra` (raylib submodule untouched; the flags are on the `Boing` target only). Deliberately *not* `-Wconversion` (the raylib int APIs make float→int narrowing pervasive and it'd flood the build), and `-Wno-unused-const-variable` because `sound.c` keeps a full C0..B8 note-frequency table as a reference (unused pitches are intentional). The raylib target gets only `-Wno-tautological-compare` on Clang to silence an upstream stb_vorbis pointer-wrap diagnostic without modifying the submodule.
- **clang-tidy runs on every build** (LLVM defaults via `.clang-tidy` — `clang-analyzer-*` only, kept minimal because the wider modules flood a raylib game with float↔int narrowing noise; warnings don't fail the build). It's scoped to our target (the `C_CLANG_TIDY` target property), never the submodules. `HeaderFilterRegex: 'include/.*\.h$'` in `.clang-tidy` extends it to our own headers while keeping raylib's and nanosvg's out.
- **clang-format** (LLVM style via `.clang-format`): `cmake --build build --target format` reformats `src/*.c` + `include/*.h` in place. Both tools are gated on being found, so a machine without them still builds.
  - **The tree is format-clean as of 2026-07** (`ba53884`'s follow-up), so the target is now a no-op unless you've actually drifted — run it freely. Keep it that way: it globs *everything*, so if the tree is ever allowed to drift again, one run mid-feature reformats files you never touched and buries the real diff. Check with `clang-format --dry-run -Werror src/*.c include/*.h`.

      - `gTheme` is **zero-initialized until the first `themeUpdate`**, so anything a test seeds from `gTheme.confetti[]` before then is transparent black and renders invisible.
    Their asserts cover the two failures this art path produces *without* crashing: a texture that never baked leaves the frame blank, and a `BeginBlendMode` whose `EndBlendMode` is missing leaks additive blending into everything after it and blows the frame to white.

## Layout

Code is header/impl pairs in `include/` + `src/`. Two groups: **screens** (one file per FSM state, all built on the shared `Game` context) and **subsystems** (the reusable engine underneath).

```
src/main.c            loop + STATES[] dispatch table + music state/layers
src/game.c            Game context plumbing: transitions, high score, shared button geometry
src/screen_splash.c   SPLASH   - startup logo, drains the cheap art preloads
src/screen_menu.c     MENU     — attract demo, button column, help/missions overlays
src/screen_shop.c     SHOP     - component outfit picker + power-up upgrade cards
src/screen_credits.c  CREDITS  — CRT zoom-out + scrolling credits reel
src/screen_play.c     PLAYING/PAUSED/GAMEOVER — HUD, pause overlay, run-summary card
src/{theme,player,world,background,sound,ui,svg,font,tex,post,settings,persist,progress}.c   subsystems
resources/BoingIcon.{svg,icns}   original Finder/Dock app icon source + bundle resource
cmake/{Info.plist.in,CheckBundleSize.cmake}   bundle metadata + hard size guard
```

## The game loop and FSM

`src/main.c` owns the loop and nothing else. The FSM is explicit: a `Game` context struct (`include/game.h`) threaded through a `STATES[]` dispatch table that maps each `GameState` to `{update, draw}` function pointers — the loop is just `STATES[state].update(&game)` then `.draw`. `STATES[]` is unsized, and a `STATIC_ASSERT` ties its measured length to `GAMESTATE_COUNT` so a missing handler fails the build.

States: **SPLASH** → MENU (once, via a black dip), **MENU** ⇄ SETTINGS / SHOP / CREDITS, MENU → **PLAYING** ⇄ **PAUSED**, PLAYING → **GAMEOVER** → PLAYING (retry), pause/game-over HOME → MENU, menu EXIT sets a `quit` flag that ends the loop.

- **Transitions** route through `gotoState`, which records `prevState` — that's how SETTINGS knows which screen to return to (and `drawSettingsState` knows which screen to draw underneath itself). `startTransition(g, next)` instead starts a **black dip**: the loop ramps `fade` to 1, swaps state at the bottom, ramps back. Only the splash→menu handoff uses it today.
- **Physics runs on a fixed 60Hz timestep accumulator** (`screen_play.c`), so gameplay is framerate-independent. `world->hitstop` skips whole steps for impact freeze, and `player->crouch` skips the input+gravity half of a step for the run-start wind-up (see **player**).
- **Music follows the FSM**: `trackForState` maps UI states to `TRACK_MENU`/`TRACK_GAMEOVER` and gameplay to `themeTrack()`, pushed every frame via `setTrack`; `updateMusicLayers` separately feeds live combo, fall-danger, and finale strengths to `setMusicDynamics`.

### Rendering model

Every draw handler works in **fixed 800×800 logical coords**, and the loop wraps the whole frame in an rlgl scale matrix (`rlPushMatrix`/`rlScalef(postScale())`) so it **rasterizes natively at the window resolution** — crisp vectors, no upscaled-texture blur, no letterbox — without touching draw code. `FLAG_WINDOW_HIGHDPI` is set before `InitWindow` so `GetScreenWidth`, the mouse, and `BeginScissorMode` all stay in logical **points**; without it a resized non-HiDPI window reports doubled pixels and the scene overflows.

The frame does not go straight to the window: the loop brackets the draw with `postBegin()`/`postEnd()` (the **post** subsystem), so it lands in a **supersampled offscreen target** that is then resolved through one post-processing shader. The **custom mouse pointer is the one thing drawn after the resolve** (`drawCursor()`, between `postEnd` and `EndDrawing`), in raw window points rather than 800-space — inside the pass, the credits CRT barrel would slide it off the real cursor and Fog would blur it. Two consequences for draw code: the frame's scale factor comes from `postScale()`, not `GetScreenWidth()/800` (the target is bigger than the window), and anything that escapes the matrix must use that same factor — `screen_credits.c`'s scissor is the only such place. Inside a bound framebuffer `BeginScissorMode` takes its no-DPI-scaling branch and works in raw target pixels, which is exactly what `postScale()` hands it.

**Points vs pixels at the resolve.** The target is sized in **pixels** (`GetRenderWidth()`), but `postEnd` blits it back over a rect in **points** (`GetScreenWidth()`) — not a bug to be "fixed". `EndTextureMode` restores raylib's HiDPI `screenScale` matrix (`lib/raylib/src/rcore.c`), so the backbuffer is back in point space by the time the resolve quad is drawn; matching the two to each other covers a quarter of the window on a 2× display.

In-game the world scrolls under a plain `rlPushMatrix`/`rlTranslatef(-cameraY)` rather than `BeginMode2D`: `BeginMode2D` does an `rlLoadIdentity` and its `EndMode2D` restores raylib's HiDPI `screenScale`, both of which discard the frame's own scale matrix and leave every screen-space draw after it (HUD, pause overlay, game-over) doubled on Retina. HUD/overlays draw after the matching `rlPopMatrix`, back in the frame's scaled 800×800 space.

There are exactly two `RenderTexture`s: post's scene target (above) and `gMenuSnap` — a menu freeze-frame written by the menu screen and zoomed by the CREDITS CRT effect. The menu snapshot is captured in the *update* pass, before `BeginDrawing`, so it never nests inside the post target.

**Icons and glyphs are textures, not primitives.** The `svg` subsystem rasterizes each one once into a mipmapped `Texture2D` and `DrawTexturePro`s it, which sits slightly against the crisp-vector model above: a texture has a fixed pixel size. The mitigation is to rasterize far above the worst-case device size and only ever downsample (mipmaps + trilinear), never upsample — see `SVG_ICON_PX`/`SVG_LOGO_PX` and their sizing arithmetic in `svg.c`. **If a glyph starts drawing much larger than it does today, its raster size has to grow with it** or it will go soft. **Text is the same deal** — the `font` subsystem's atlas is one 128px cell per glyph, sized against the 80pt menu title at the worst-case `postScale()`. Everything else on screen is still immediate-mode primitives.

`FLAG_MSAA_4X_HINT` is still set alongside the HiDPI flag, but it is **no longer what antialiases the scene**: a `RenderTexture` can't be multisampled (there is no multisample-FBO path in rlgl), so routing the frame through post's target would have dropped MSAA entirely. Post's 2× supersampling replaces it, and beats it - it also smooths gradient interiors and the generated font atlas, which MSAA never touched. The flag now only covers the fallback path where post switched itself off. The vector glyphs never depended on either — nanosvg antialiases at raster time.

### Shared context — `game.h` / `game.c`

`Game` holds everything mutable: player, world, settings, progress, high score, the fixed-step accumulator, and the per-screen flags (`showHelp`, `creditsAnim`, `fadePhase`, …). `game.c` holds only what more than one screen needs:

- transitions: `gotoState`, `startTransition`, `returnToMenu`, `startGame(fromMenu)` (fromMenu carries the attract blob straight into play, so PLAY is seamless; retry respawns — either way it ends with `beginJump`, so every run opens on the crouch);
- `loadHighScore`/`saveHighScore` (keys in the shared `save.json`);
- button geometry `centeredBtn` / `centeredRow` and the `drawCoinGlyph` mini-coin;
- `gMenuSnap`, and the SETTINGS bridge (`updateSettingsState`/`drawSettingsState`) that draws the return context underneath the options overlay.

**Button convention**: each button is one `static` rect helper in its own screen file, referenced by `uiButton(rect, ...)` in `draw()` and by `uiItem(rect)` in the matching `update()` - declared once, used in both. All menus/overlays are fully mouse-playable; keyboard paths run in parallel.

## Screens

- **SPLASH** (`screen_splash.c`) - the gold serif "H" wordmark (`SVG_LOGO`, drawn twice: an offset near-black shadow pass, then the glyph itself) plus a spinning ring loader, on white. `updateSplash` drains the full SVG and generated-texture queues in its first update and bakes the font atlas once. Those art queues cost only about 30ms each in total; stepping one item per rendered frame used to add 38 frames of idle wall time. The main loop separately calls `audioPreloadStep()` every frame, with menu music first, so the first splash update can start the black dip immediately and the remaining tracks bake behind it. `updateAudio` remains disabled while the state is SPLASH, so loading stays silent.
  - **There is no minimum hold and no skip key.** Startup now consists of the real art work plus the existing black dip; unrelated gameplay music no longer holds the main menu behind it.
  - **Expensive precomputation belongs in a stepper.** `initAudio` bakes nothing. Audio stays one track per frame; the cheap art steppers are drained together so their queue length does not become artificial wall time. The one remaining lazy init is post's shader compile + target allocation on the first `postBegin()`.
- **MENU** (`screen_menu.c`) - runs **attract/demo mode** (`updateAttract` wanders the blob); Space/PLAY carries that same blob into gameplay. Buttons: PLAY / SHOP / MISSIONS / SETTINGS / CREDITS / EXIT plus a `?` in the corner. Both overlays leave the dimmed live menu visible around the modal; the MISSIONS panel itself is opaque so menu UI cannot show through it. MISSIONS has three keyboard/mouse tabs: DAILY shows three date-selected cumulative tasks, REPEATABLE shows the three carry-over loops, and ACHIEVEMENTS contains the five original permanent milestones. Task rows stay read-only because `bankRun` pays rewards automatically; only the tab strip and shared close button are interactive. The help overlay is static `HELP_LINES` text, no interactive walkthrough; it is bounded on **both** axes (`HELP_STEP` must keep the last line clear of the close button at y=568, and no line may measure wider than the 600px panel, since `drawCenteredText` does not shrink to fit like `uiButton` does). Pressing CREDITS snapshots the live menu into `gMenuSnap` before switching; if that optional target failed to allocate, the pull-back uses channel static instead.
- **SHOP** (`screen_shop.c`) - the coin economy. Four outfit cards (color / headwear / eyewear / mouth-wear) show the equipped components. Activating one opens a compact modal over the shop with that category's eight choices; owned choices equip, unowned choices buy and auto-equip, and only the modal is interactive until DONE/Esc. Preview pieces use `drawBlobBody` + `drawAccessories`, the same art as the live player. Selecting a body color also updates the shared UI accent immediately. Below them, each **per-power-up upgrade card** (`SHOP_PU[]`) shows its name, icon, and 1-3 vertically stacked axes (`-1` pads Shield/Debuffs); each axis has the next cost or MAX plus a five-segment level bar. Catalogs and costs live in `progress`; this file is layout + click routing only.
- **CREDITS** (`screen_credits.c`) - the frozen menu picture **pulls back into a retro CRT set** (`drawCrtCabinet`: wood shell, speaker grille, dials, power LED, rabbit-ear antennae, all scaled by the eased zoom `e`), cuts to a burst of channel **static** (`drawStatic` - one `TEX_STATIC` blit with a per-frame jittered source offset, valid at *any* offset because the texture is `GL_REPEAT`, plus sweeping roll bars; the source rect is half the destination in texels so one noise pixel covers a 2×2 block and the snow doesn't shimmer to flat grey under the post pass's supersampling), then plays a looping **credits reel** (`drawReel` scrolling `REEL_LINES`; lines starting with `-` use the selected UI accent, and a fixed three-row gap separates the end from the copy appended behind it). The reel uses `Game.creditsScroll`, reset when CREDITS is pressed, rather than process-global time, so every visit starts at the title. The tube itself is handed to the `post` pass as `crtRect` - barrel bulge, chromatic split, scanlines and phosphor mask all ramp in with the zoom `e`, replacing the `DrawLine` scanline loop this file used to run every frame. BACK/Esc/Space only responds once fully zoomed out, and reverses the zoom before returning to MENU. Credit text is a homage note only, per the design philosophy above.
- **PLAYING / PAUSED / GAMEOVER** (`screen_play.c`) — `P` or the pause button pauses play; `P` or `Esc` resumes. One `drawPlay` for all three: background, world under the camera translate, power-up aura, player, the theme's edge-safe foreground depth layer, then the HUD and state-specific overlay (pause button / PAUSED panel / summary card). It also fills the frame's `post` mailbox — bloom from `themeGlow()`, and the Fog debuff, which is now a blur + drifting haze in the post pass rather than the flat dim rect it used to draw here. Fog therefore covers the HUD too; that is deliberate (it's a hazard), and the blur is kept light so the score stays readable. `drawHud` stacks a score badge (top-left), a coin tally right below it (kept off the top-right so the pause button never hides it), a top-center LEVEL progress bar, a `COMBO xN` readout under it (font grows with the combo, shown only while a chain runs), a ~2s era-name callout on each level-up (`world->levelBanner` — the band changes the *rules*, so the HUD says which era you just walked into), and one timer bar per active power-up. Game over draws `drawSummaryCard`: height / coins / best combo / era reached (`ERA_NAMES`, `STATIC_ASSERT`ed to be one name per `THEMES[]` row) over SCORE/BEST, titled "NEW BEST!" in gold on a record run.

## Subsystems

- **core** (`core.h`, header-only) — `GameState` enum, shared screen constants (`SCREEN_WIDTH`/`SCREEN_HEIGHT`/`FLOOR_Y`), the `clampf` math helper, and `STATIC_ASSERT` (C99 has no `_Static_assert`, so it's the negative-array-size trick). Modules read these instead of taking screen-size parameters.
- **theme** (`theme.h`/`theme.c`) - the palette is **runtime state** (multi-theme). `Theme` is a struct of every altitude-driven scene `Color` (sky/sun/cloud/coin/grass/monster/power-up + `confetti[CONFETTI_COUNT]`) plus a `backdrop` style and a `track` id. `THEMES[]` is the table - **five retro-era levels** in climb order: 0 = Sunny Hills (day sidescroller), 1 = Birdsong Skies (open sky and birds), 2 = Night Blocks (voxel-survival night), 3 = Neon Maze (dot-muncher arcade), 4 = Falling Blocks (falling-piece puzzle). Each is a genre homage, never a named product. **The band index is not only a palette** - `world.c`'s `worldEra()` reads the same number and swaps the *mechanics* with it (see **world**), so a new theme row is also a new gameplay slot. Adding a level is one more row (plus a `BackdropStyle` case, a `TRACKS[]` row, an `ERA_NAMES[]` row, and a decision about what it plays like). `THEME_COUNT` is a **macro** so enum-parallel tables elsewhere (`ERA_NAMES`) can be checked at compile time; `theme.c` static-asserts the table actually has that many rows.
  Each frame `themeUpdate(ascent)` recomputes the global `gTheme` by lerping the whole leading run of `Color` fields (via `offsetof(Theme, backdrop)`, itself static-asserted to land on a whole number of `Color`s) between the two neighbor themes over `BAND_HEIGHT` (~20000 units of climb) - so the **whole scene morphs continuously** as you climb. The named scene-color macros (`COIN_HI`, `CLOUD`, `GRAPE`, `SKY_TOP`, …) read `gTheme`; `UI_ACCENT` / `UI_ACCENT_DK` instead read the selected outfit colors set by `setPlayerCharacter`, so the interface follows customization without being overwritten by `themeUpdate`. **Static initializers cannot use these macros** (they're runtime lvalues), so `POWERUP_DEFS[]`, the fallback `gCharacter`, and the cosmetic color catalog use fixed raylib constants / literal `Color`s. `drawMenuBackground` seeds the menu palette, while `drawGameBackground` updates it from ascent. `themeBlend(&lo,&hi,&f)` exposes the neighbor indices + factor for the background crossfade; `themeBandProgressAt(ascent)` gives audio the same private band-height calculation without duplicating its constant; `themeGlow()` gives the bloom weight from a small `GLOW[]` table (a separate table, not a `Theme` field, because the struct's leading run must stay all-`Color` for the generic lerp - `STATIC_ASSERT`ed like the rest) - it drives **both** the post pass's bloom **and** every additive stamp in `world.c`, so it is the one knob for how hard the arcade eras blaze, and row 0 is a small non-zero rather than a flat 0 because real daylight blooms too; `themeTrack()` gives the current music track (it holds the *current* level's track for the whole band, so the music crossfade lands on the level boundary, not mid-band).
- **player** (`player.c`/`.h`) - pure physics + input, knows nothing about the level. `Player` is float `Vector2` position/velocity/acceleration + `radius`, plus a `trail[TRAIL_LEN]` ring buffer. `createPlayer` returns the canonical spawn state (gravity lives in `acceleration.y`); `handlePlayerInput(player, targetX, dir)` reads arrows and, with no arrow held, steers toward `targetX` (the mouse column; a sentinel outside the screen ignores it) - `dir` is `+1` normally and `-1` while Dizzy, flipping arrows and mouse-follow alike; `updatePlayer` integrates, damps, **stops at the side walls** (the blob's radius stays inside the screen), and pushes the trail; `updateAttract` is the menu demo (wander toward a random target between those walls, bob at the floor line). `beginJump`/`updateCrouch` are the **run-start wind-up**: `beginJump` (called by `startGame`) plants the blob **1px above** `FLOOR_Y` and sets a `crouch` countdown; while it runs, `screen_play.c` calls `updateCrouch` in place of input+gravity (but still runs the world, or every coin and platform would pop in at release). That 1px gap is load-bearing - it's what holds off `updateWorld`'s floor-bounce test, and **the bounce is the launch**, particles/shake/SFX included, so there is no launch code of its own. The deform rides one `squash` field (>0 crouch, <0 pop), which the release frame snaps negative and `updatePlayer` decays back to round. `drawPlayer` renders a **flat, solid two-tone candy blob** (deliberately un-bubbly - no glow/rim-ring/sheen): motion trail (soft `TEX_PUFF` stamps - eight crisp ellipses behind the blob read as eight blobs, not as an afterimage; **the body itself is untouched**, the most hand-tuned art in the game), squash-&-stretch from `|velocity.y|` (**magnitude, not sign** - a rise stretches tall exactly like a fall; it used to flatten while rising) plus that `squash` deform with the feet pinned, googly eyes whose pupils lean toward movement + a catch-light each, cheek blush, expression-driven eyebrows, and an expression mouth selected by `player->expression` (`Expression` enum: HAPPY / NEUTRAL / SAD / DIZZY, the last swapping in spiral eyes + a dazed "o"). The composed `Character` carries body colors plus three wearable ids; `createPlayer` stamps the `gCharacter` module global (set by `setPlayerCharacter`, which also applies those body colors to the shared UI accent) so its call sites stay arg-free. The attract wander state lives on `Player` - no hidden statics.
  - The three accessory slots (`hat`, `glasses`, `mouthwear`) map `HatId` / `GlassesId` / `MouthwearId` through `HAT_SVG[]` / `GLS_SVG[]` / `MOUTH_SVG[]` to fixed-color `SVG_ACC_*` art. NONE is enum row 0 with no glyph, and each positional `id - 1` table is `STATIC_ASSERT`ed complete. Mouth-wear suppresses the procedural expression mouth and draws in front of the completed face; glasses and hats share that final foreground pass.
  - The body and accessories are split into `drawBlobBody` / `drawAccessories` so shop previews use the live art. Both take deformed half-extents `(rx, ry)`: all three accessory boxes scale with squash/stretch through their `*_W` / `*_H` / `*_Y` tuning knobs, so pieces stay attached during the run.
- **world** (`world.c`/`.h`) — level content, camera, score. World-space coordinates, up = −y; the camera (`cameraY`, top of view) only moves up, except that it chases a fall up to `DEATH_DROP` past the peak. Fixed pools follow one spawn-above-view / cull-below-view idiom: `Coin` (trail with random-walk x, ~55px apart; **early levels are richer** — while `world->level < COIN_DOUBLE_CAP` each row also drops a bonus coin beside the trail coin), one-way `Platform`s (~300px apart, swept feet check, no tunneling — the sweep is in the *platform's* frame (`p.y - vy`), which is what keeps a falling era-4 pad from being tunnelled by its own motion), `Monster`s (~900px bands, drift horizontally; a hit is **not lethal** — it knocks the player down and scatters/costs coins, or, while invincible, splatters the monster; both outcomes are one shared function each, `hitPlayer` / `splatMonster`, because the falling blocks reuse them), `PowerUp`s (~1500px), and `Particle`s (radial burst, gravity + decay). Three file-scope macros unify the pools: `FIND_FREE`, `FOREACH_ACTIVE`, `CULL`; spawn stays per-type (each pool's logic genuinely differs). Tuning knobs (`COIN_BOOST`, `PLATFORM_BOUNCE`, `SHAKE_*`, …) are `#define`s at the top — game feel is hand-tuned there.
  - **Each era plays differently, not just looks different** — this is the identity of the game, and it all hangs off one query, `worldEra()` (= `world->level % THEME_COUNT`; levels are infinite and themes loop, so the *mechanics* loop with the art). One rule per band: **0 Sunny Hills** is the untouched baseline jumper; **1 Birdsong Skies** cloud platforms drift horizontally (`vx`) and reflect at the screen edges; **2 Night Blocks** platforms crumble a beat after you land (`fragile`/`fuse` on `Platform`, `CRUMBLE_FRAMES`); **3 Neon Maze** is the dot-chase loop - monsters stop drifting and hunt you (`steerGhost`, capped hard on `GHOST_VY` so a ghost crowds your climb but can never keep pace with it), until a `POWERUP_PELLET` frightens them into fleeing and you eat them for a doubling `GHOST_EAT_BONUS` chain; **4 Falling Blocks** platforms *are* tetrominoes - a `shape` index into `background.h`'s shared `TETRO[]`, descending at `vy`, colliding as **one box per cell** (`padBoxes`, built from the same offsets `drawTetromino` draws with, so a T's notch is genuinely empty space), landing on the topmost crossed cell, and crushing you from below or the side. Three rules of thumb when adding to this. The era is **stamped onto the entity at spawn** (a pad born on Night Blocks stays fragile), never re-read at use time, so nothing changes the rules underfoot as the boundary passes; the era-3 rules that can't live on an entity (frightened ghosts, the pellet coin lane) read `world` state at draw/update time instead; and **anything you make move vertically needs its look stamped at spawn too** — `entSeed` hashes the live y, so giving ghosts a `vy` re-rolled a monster's whole face every frame until `Monster.seed` was added, and a falling pad's color keys off its `shape` for the same reason. `checkEras()` in the `WORLD_SELFTEST` is what proves the gates still fire — the art is unaffected when they stop, so nothing else would notice.
  - **Power-ups are table-driven**: `POWERUP_DEFS[POWERUP_COUNT]` (duration/color/label/spawnWeight/pickupShake/invincible/debuff) indexed by `PowerUpType`, with per-type timers in `powerTimer[]`. A new power-up **or debuff** is a new enum value + one table row (`STATIC_ASSERT`ed complete — a dropped row would divide by zero in the HUD bar). Five good (Magnet, Rocket, Balloon, Shield, Pellet — the last one era-gated to Neon Maze by a `spawnWeightOf` case, weight 0 everywhere else, which is enough to make `pickPowerup` unable to choose it) and four **debuffs** to dodge (Anchor/heavier gravity, Dizzy/reversed steering, Fog/screen murk, Butterfingers/can't collect coins). Debuffs are just rows with `debuff=true`: `collectPowerups` gives them a SAD face + `SFX_HIT` and no upward boost.
  - **Effects that live outside the table**: `worldInvincible()` reads the `invincible` flag so monster immunity is a query, not a per-type case; `worldInputDir()` (−1 while Dizzy) and `worldFog()` are the parallel queries for the two debuffs whose effect lives elsewhere — Dizzy in `player.c`, Fog in the `post` shader, raised by `screen_play.c`. Shield needs no effect code at all — it's an `invincible=true` row whose `duration` is a **flag** (`1.0f`, skipped by the tick-down) so it persists until monster contacts deplete `world->shieldHits`. The Pellet is the same trick used for an era: `invincible=true` is already the whole "eat the ghost" rule, because plowing through a monster while invincible is what `updateMonsters` has always done. Butterfingers is a one-line early-return in `collectCoins`. Dizzy's face is re-forced every frame in `updateWorld` so a coin grabbed mid-spin can't clear it early.
  - **Difficulty ramps with altitude**, keyed on the monotonic `world->level` (capped at `DIFFICULTY_CAP` via the `difficulty()` helper): monsters thicken/speed up/tighten their bands (`GetRandomValue(0,4) <= d`, so 1/5 of bands carry one even at L0), debuffs ramp 0→3/5 (`spawnPowerups` rolls `GetRandomValue(0,4) < d` — strictly-less, so L0 is all good — then `pickPowerup(bad)` weighted-picks within the category), and coins thin from 2-per-row to 1.
  - **Purchased upgrades** hook in via `worldSetUpgrades(const int *puLevel)` — a module global `gPuUpg[]` set per run, indexed by `PuTrack` (mirrors the `gTheme` pattern so `createWorld` callers stay unchanged). Per-level magnitudes are tuning knobs here (`EFFECT_STEP`/`DUR_STEP`/`SPAWN_STEP`), not in the shop table. **Effect** scales magnet radius / rocket thrust / balloon lift (`effectMul`) and seeds Shield's multi-hit charge `1 + level`; **Duration** scales good power-up timers (`durMul`); **Spawn** adds weight in `pickPowerup` (`spawnWeightOf`); **Fewer Debuffs** subtracts its level from the good-vs-bad roll, thinning debuffs to zero once it reaches the altitude level.
  - **Juice**: `updateWorld` owns floor/platform bounce, coin-collect boost, magnet pull, rocket thrust, balloon lift, anchor extra-gravity (placed before the rocket overwrite so rocket still wins), monster hits, decaying `shake` and `flash`, plus the **coin combo** (`world->combo` — each chained coin raises the multiplier and with it pop size, screen shake, and SFX pitch via `sfxPitched`; adds a rising `comboBonus` and tracks `bestCombo`; resets on a floor drop, a monster hit, or a `COMBO_TIMEOUT` idle) and **hit-stop** (a few-frame full physics freeze on monster impact, which `screen_play.c`'s fixed-step loop honours by skipping whole steps). Game over is `isPlayerFallen(...)`; `getScore` = ascent/10 + 5·coins + `comboBonus`.
  - **Drawing** is all cartoon: grassy ground, cloud-pad platforms (`drawCloudPad` draws a **defined solid board** so the jump-off edge reads clearly; it also carries the three per-era pad looks - wind trails while `vx` is nonzero, cracks + a shake-and-fade death rattle while `fuse` runs, and `drawFallingPiece`, which uses `background.c`'s `drawTetromino` over the shared `TETRO[]`, then adds a dark foreground silhouette, white safe-top rails, warm crush edges, and short fall trails), minted coins (rim + rotating glint + seed-varied face emblem + out-of-sync sparkle), wobbling grape monsters (drop shadow, rim light, wobbling legs, seed-varied horns/eyes/mouth, angry brows), bobbing power-ups, confetti-fleck particles, and the pop ring. Coins get deterministic per-instance variety from `entSeed(y)` — a stable hash of the spawn y, no struct field — which is **only valid for something that never moves vertically**; monsters now carry a `seed` field stamped from it at spawn, because a Neon Maze ghost drifts and a live hash strobed its face. `drawPowerUp` is a per-type `switch` (horseshoe magnet, multi-flame rocket, glossy balloon, crested shield, plus the pellet's fat pulsing dot and four hazard-styled debuff icons), split so the halo/bob-free `drawPowerupGlyph` can be reused by the SHOP cards. Those glyphs are **layered vector art**: each is several theme colors and a texture tint is uniform, so a glyph is one `drawSvg` per color role, back to front (see the `SVG_PU_*` block in `svg.c`). Their shared 24×24 viewBox is scaled so **12 units == `POWERUP_RADIUS`**, which is why every `R * k` in the old primitive code reads as `12 * k` in the path data — keep that mapping when editing them. Three effects stay procedural because they reshape every frame and no fixed picture can stand in: the rocket's flame, the balloon's wavy string, the magnet's blinking spark. `drawPowerAura` draws one slow color-coded wisp and mote per active power-up over broad breathing `TEX_PUFF` light, all additively behind the blob so its silhouette and face stay clear. The bright wisp cores feed the existing post bloom, avoiding another shader or render target.
  - **Every glow in the file goes through one helper, `glowStamp`** — an additive `TEX_PUFF` behind the coin, monster, power-up halo and pop ring. It takes a `base` weight *plus* a `lit` weight scaled by `themeGlow()`, rather than scaling by `themeGlow()` alone: the day era's glow is near zero, and weighting it out entirely would leave daylight coins flatter than they were before the texture pass ever ran. Sunny Hills keeps the light it always had; the neon eras blaze on top. Soft shadows (monster, cloud pad) are the same texture drawn *dark* on normal blend, and the pad's three backing puffs are the backdrop's own `TEX_CLOUD`, so a platform reads as the same weather as the sky it hangs in.
  - **Particles are two passes, not one**: an additive `TEX_PUFF` streak pass for the light, then the original solid confetti flecks on top. Additive alone vanishes against the daylight sky, which saturates to white — and a coin burst is supposed to be confetti. Two blend switches for the whole pool, never one per fleck.
  - The ground's soil takes tiled `TEX_ROCK` grain at a **small** tile (70px): the texture is only 8 cells across, so a large tile turns soil into cobblestones.
  - Coins, monster bodies and the pad's board **stay primitives**. Swapping an ellipse or a rounded rect for a texture of the same shape buys nothing, and the pad's crisp board edge is load-bearing for reading the jump-off point.
- **background** (`background.c`/`.h`) - procedural depth layers, no assets, **theme-aware**. `drawGameBackground(cameraY)` calls `themeUpdate(ascent)`, draws the sky gradient from the blended `gTheme` (so it morphs continuously with altitude), then crossfades the two neighbor themes' backdrop *shapes*. Shapes cannot lerp, so they alpha-crossfade only over the **last ~15% of the band** (`BACKDROP_XFADE_START`), keeping the next level's decor out until the boundary is close. `drawGameForeground(cameraY)` applies that same crossfade after the world and player; its near-camera details stay in the outer ~60px so they can overlap the scene without hiding gameplay: meadow sprigs, close cloud banks, voxel-island edges, neon rails, and clipped tetrominoes. Five backdrop styles share one parallax idiom (`parallaxDepth`/`wrapf`), each dressed with theme-specific detail built from small reusable shape helpers: `drawHillsBackdrop` (storybook valley with layered mountain and meadow ridges + patchwork fields + winding river + cottage + textured trees/clouds), `drawSkiesBackdrop` (open azure air + layered high cloud banks + wind ribbons + animated migrating birds), `drawStarsBackdrop` (moon with craters + twinkling stars + a periodic shooting star + floating grass-topped voxel islands), `drawMazeBackdrop` (scrolling **broken-corridor** neon maze via a per-cell `hash2` + pellets/pulsing power-pellets + drifting ghosts + a chomping hero), and `drawBlocksBackdrop` (a faint playfield "well" grid + muted, translucent falling **tetrominoes** from `TETRO[]`, deliberately quieter than gameplay pieces). `TETRO[]` and `drawTetromino` are the **one thing this module exports beyond the three draw entry points**, because `world.c`'s Falling Blocks platforms are literally those shapes - the table's cell offsets are non-negative precisely so the same `origin + d*cell` serves as both the art and the collision boxes. `drawMenuBackground` seeds `themeUpdate(0.0f)` (the menu is always level 0) then draws sky + sun + big drifting clouds.
  - **Atmosphere uses `tex`; crisp silhouettes use shapes.** Clouds use one shaded `TEX_CLOUD` underpaint plus three body stamps; Sunny Hills reuses the same texture for painted tree crowns and elongated foreground leaves, while its mountain/meadow planes are filled spline ridges. The sun/moon halo is one additive `TEX_PUFF`; the night sky is two parallax-scrolled tiled `TEX_STARFIELD` quads (only the nine *bright* stars remain shapes because they twinkle); the three dark backdrops carry a vertically-wrapped `TEX_NEBULA` haze; the voxel islands take `TEX_ROCK` grain **over their rectangular body only**. Ghosts and tetromino cells stay stacked shapes on purpose - cheap, readable, and not improved by a texture.
  - **The whole neon maze lattice draws inside one `BLEND_ADDITIVE`** wrapping the grid loop, not one per rect: `BeginBlendMode` flushes the batch, so per-cell switching would cost ~180 flushes a frame. The ghosts and the hero stay on normal blend — they are characters lit *by* the maze, not part of it.
  - **Two sign traps in the starfield scroll**, both already solved in `drawStarfield`: climbing makes `cameraY` negative, and a *source rect* scrolls the opposite way a position does (a growing `srcY` pulls content up), so the offset is negated twice over. The wrap is seamless because it is modulo one tile and the texture is `GL_REPEAT`, which also swallows the negative coordinate. The `TEX_NEBULA` haze is deliberately **not** tiled — perlin has a hard seam at its own edges, so it wraps as two stacked quads instead.
- **sound** (`sound.c`/`.h`) - procedural chiptune **plus procedural SFX**, no sample files, **per-theme**. `TRACKS[]` is the table (`STATIC_ASSERT`ed against the `MusicTrack` ids): each row is a note array + loop `duration` + a `Timbre` (lead voice: warm / soft / pulse / square; bass notes below C3 always fall back to warm so the oom-pah never buzzes) + a `DrumStyle` (baked percussion on a 0.5s beat grid: none / four-on-the-floor / driving) + an `echo` wet mix. Seven tracks: five full original level melodies (`NOTES_NATURE` 32s, `NOTES_SKIES` 16s airy, `NOTES_NIGHT` 32s calm, `NOTES_MAZE` 16s driving chase, `NOTES_ARCADE` 64s), plus menu and game over. **Each track's duration must be a whole number of seconds** so the shared 110Hz A2 tonic-pedal pad has whole cycles at the loop seam.
  `buildLoop(track)` bakes one full loop into `loopBuffer[track]`: each note walks only its live sample span, then the pedal, drums, seam-safe two-tap echo and peak normalization are applied. The old sample-first loop tested every note against every sample and dominated startup, especially on the 64-second track; loop inversion preserves the generated samples exactly while cutting the then-six-track CPU time from 1.64s to 0.31s on an M-series Mac. A failed allocation leaves the slot NULL and the track plays silent. An unavailable audio device or invalid stream also degrades to silence; update and shutdown validate the stream before touching it. **`initAudio` bakes nothing** - `audioPreloadStep()` attempts menu music first, then one remaining track per main-loop frame while the splash dip runs. A track whose bake has not run yet has `loopSamples 0` and reads as silence.
  `updateAudio` streams 4096-sample chunks with a **per-track `loopPos[]`**. Switching is `setTrack(track)`: it **crossfades (~2s, `FADE_SAMPLES`) only between two level tracks**, and hard-cuts for anything involving menu/game-over, so no music bleeds across a UI boundary. `setMusicDynamics` adds tiny streamed layers over those buffers: hats enter at combo 3, then kick/snare as the chain rises; a double low pulse scales with fall speed and screen depth; and an original eight-note countermelody plays in the last quarter of every Falling Blocks band. A monster hit drops the arrangement to its low-passed bass for 0.4s and restores it over 0.8s. Level-up uses one short fanfare transposed by an enum-complete per-era pitch table. All of these are synthesized against the current track's beat position, so they add no asset or loop buffers. SFX ride the same stream: a fixed 8-voice pool, each effect synthesized per-sample in `renderVoice` (square/sine/saw + decay envelope, a `sweep()` helper, `noise()` for crackle, lengths in `sfxLen[]`, also `STATIC_ASSERT`ed complete), with a **neon variant** (harsher/brighter) selected on the neon levels, summed through a `tanhf` limiter. Public triggers: `sfx(SfxId)` and `sfxPitched(id, pitch)` (the pitch scales sample-time `t`, shifting every frequency uniformly with the duration unchanged; that's the rising coin-combo blip). Music and SFX have **independent levels** (`setVolumes(music, sfx)`, driven by the settings screen) rather than one master volume.
- **ui** (`ui.c`/`.h`) — mouse-driven UI + shared text helpers, no assets. `virtualMouse()` maps window mouse coords (logical points) into the fixed 800×800 draw space so hit-testing matches the scaled draw; `mouseInRect` tests against it and `clicked(rect)` is true on the frame a left-click lands inside. **All four text helpers live here and nothing else in the game calls raylib's `DrawText`/`MeasureText`**: `uiText` and `uiTextWidth` are the bare draw and measure, both going through the `font` subsystem's `gameFont()` with a spacing of 0 (letterspacing is baked into each glyph's advance); `drawTextShadow`/`drawCenteredText` layer the shared drop shadow and centering on top and are what every screen actually calls. `uiTextWidth` returns `int` on purpose — it is a drop-in for `MeasureText`, and every call site does integer arithmetic on the result. `uiButton(rect, label, icon)` draws a rounded cartoon button with hover highlight + optional icon + a label whose font shrinks to fit (draw-only; pair it with `uiItem(rect)` for activation). `drawIcon(kind, …)` draws every icon (`ICON_PLAY`/`PAUSE`/`GEAR`/`RETRY`/`BACK`/`HOME`/`EXIT`/`HEART`/`SHOP`/`MISSIONS`, plus `ICON_NONE`) as a vector glyph via the `svg` subsystem — the body is just an `IconKind` → `SvgId` lookup (`ICON_SVG[]`, indexed `kind - 1` because `ICON_NONE` is the enum's first value and has no row) plus one `drawSvg`. `ICON_SCALE` converts the caller's half-extent `s` into the glyph's box side.
  - **Keyboard focus is one shared list, not per-screen state.** Screens are mutually exclusive, so `ui.c` keeps a single `gItems[]`/`gCount`/`gFocus` rebuilt every frame: a screen's `update()` calls `uiItem(rect)` in place of `clicked(rect)`, which registers the rect *and* returns "clicked, or Enter while focused". `main.c` drives the rest: `uiFocusStep()` after update picks the **nearest rect in the pressed direction**, covering columns, tab rows, and the shop grid without per-screen navigation rules; `uiFocusDraw()` after draw adds the pulsing ring and key hint above every overlay. `gotoState` calls `uiFocusReset`.
    - **Registration must be unconditional and stably ordered** — an `else if` chain or an early `return` that skips a `uiItem` call drops that rect from the frame's list and the ring jumps. That's why `updateMenu` collects every `uiItem` result into a `bool` before acting on any of them, and why the shop's BACK moved to the *bottom* of `updateShop`. Item 0 is where the ring lands on arrival, so each screen registers its primary action first.
    - **A screen that registers nothing keeps the arrow keys** and draws no ring: SPLASH (nothing to click), **PLAYING** (arrows steer the blob), **SETTINGS** (its own row cursor + slider nudge). That is the whole mechanism — there is no opt-out flag.
    - Enter is the only new global binding; every pre-existing `SPACE`/`ESC`/`S`/`P` shortcut still means what it did, which is why SPACE was *not* made a second activate key (it would collide with menu SPACE = PLAY).
  - `drawCursor()` is the candy-comet mouse pointer: a fixed pink-gold `SVG_CURSOR` over a soft `TEX_PUFF` glow, a frame-rate-independent six-point pink/gold motion trail, and a click response that compresses the arrow while an additive ring and six-ray sparkle burst expand from the exact press point. **`main.c` calls it after `postEnd()`**, in raw window points - inside the post pass the credits CRT barrel would slide it off the real cursor (`virtualMouse` has no inverse warp) and Fog would blur it. After settings applies its startup resize, `main.c` seeds the hidden pointer at the window center because raylib leaves both mouse position and `IsCursorOnScreen()` unset until the first cursor event. `drawCursor()` accepts that seeded nonzero position, but treats raylib's false flag plus `(0,0)` as a real exit and resets the trail so re-entry cannot streak across the frame. The glyph's tip is authored at its viewBox origin, so the hotspot is just a half-box down-right offset.
- **settings** (`settings.c`/`.h`) — the options screen reachable from MENU or PAUSED, with **four rows**: framerate, resolution, music volume, SFX volume. Each row is a **horizontal slider**: a generic stop model (`rowStops`/`rowStop`/`setRowStop`) maps every row to discrete stops — one per option for fps/res, 21 (5% steps) for each volume — so the knob snaps. Mouse **drags** the knob (grab band `trackHitRect`, `dragRow` tracks the held row, fraction from `virtualMouse().x`); keyboard ←/→ nudge one stop, ↑/↓ pick the row. The resolution row **defers its `SetWindowSize` until drag release** (`suppressResize` gates the resize inside `applySettings`) so the live window resize can't shift the cursor's slider fraction mid-drag. Values persist as keys in the shared `save.json`; `applySettings` pushes framerate (`SetTargetFPS`), volumes (`setVolumes` — two channels, not `SetMasterVolume`), and resolution (`SetWindowSize`, after which the loop's scale matrix fills the new window). `ROW_LABELS[]` is `STATIC_ASSERT`ed against the `RowKind` enum.
- **svg** (`svg.c`/`.h`) — the vector icon art. Every glyph is an **SVG source string baked into the binary** (no asset files: they'd count against the 1.44MB budget and add a missing-file failure mode), parsed and rasterized once by **nanosvg** into a mipmapped `Texture2D`, then drawn tinted. `SVG_DEFS[SvgId]` is the table — `{src, px}` per glyph, `STATIC_ASSERT`ed complete — and the public surface is just `drawSvg(id, cx, cy, size, rotDeg, tint)`, `svgPreloadStep()` and `unloadSvgCache()`.
  - **Why textures at all**: real curves, real holes, real antialiasing. The old `ICON_GEAR`/`ICON_HOME` faked their holes with a translucent black disc, which only looked right over one background shade; they are now transparent alpha.
  - `drawSvg` fits the viewBox's **larger side** to `size` and centers it, so the draw box is always square whatever the viewBox aspect is, and callers position by center. Content must stay **inside** its viewBox — the rasterizer clips at the box, which is why the rocket's nose and the fog's outer puffs were pulled in from their original offsets.
  - **Colors**: a tint multiplies uniformly, so anything that recolors with the theme is authored **white** and tinted per draw. Multi-color art is therefore split into **one layer per color role** and drawn back to front (the power-up glyphs, the coin's rim/face). Art whose colors are *fixed* can bake them in instead and draw tinted `WHITE` — `SVG_LOGO` carries its own gold gradient that way (and tints near-black for its shadow pass), as do `SVG_CURSOR` and the `SVG_ACC_*` accessories (a gold crown that recolored with the body would stop being a gold crown; a white-tinted cursor would vanish on the white splash).
  - `drawSvgEx(id, cx, cy, w, h, …)` is the same draw with an **independent width and height**; `drawSvg` is the square-box shorthand every icon and power-up layer uses. The non-square box exists for the blob's accessories, which have to ride a body whose `rx != ry` while it crouches or stretches.
  - **`SVG_CURSOR` is deliberately first in the enum.** `svgPreloadStep()` bakes in enum order and the pointer is drawn from the splash's first frame, so being first is what keeps it off `drawSvg`'s lazy-bake fallback.
  - **Baking** is one glyph per `svgPreloadStep()` call, but SPLASH drains the cheap queue in one update instead of tying one glyph to one rendered frame. The shared `NSVGrasterizer` is created on the first bake and **released as soon as the queue drains** (and again in `unloadSvgCache`) - it holds scanline buffers sized to the largest raster it has seen, which is the 1024px logo, and nothing needs it once every glyph is resident. A later lazy bake just recreates it. `drawSvg` also lazily bakes on first use as a fallback. A glyph that fails to parse or allocate is marked baked and draws **nothing** - quiet degradation, same contract as a music track whose buffer failed to allocate. `nsvgParse` mutates its input, so sources are copied into a scratch buffer first; one over `SVG_SCRATCH` is skipped rather than truncated.
  - Adding a glyph is one enum value + one table row + the raster size.
- **font** (`font.h`/`font.c`) — the game's own vector font, so text is not the one thing left on screen drawn in raylib's chunky 10px bitmap. Same doctrine as `svg.c`: 49 SVG paths baked into the binary, rasterized once by nanosvg into one 7×7 atlas of 128px cells and wrapped in a hand-built raylib `Font`. Public surface is `gameFont()` / `fontPreloadStep()` / `unloadGameFont()`, and **nothing outside `ui.c` calls it** — `ui.c`'s `uiText`/`uiTextWidth` are the whole text surface.
  - **The glyphs are skeletons, not outlines.** Each row is a bare path `d` string stroked at one uniform `STROKE` with round caps and joins; the `<svg>` wrapper is `snprintf`'d at bake time rather than stored 49 times over. That is what keeps them consistent with each other and cheap — ~40 bytes of path data apiece, and the whole font cost **128 bytes** of binary.
  - **The design grid is what to read before editing a glyph.** `CELL` (128) is also `Font.baseSize`, so every number in the table is 1/128 em. Ink cap top y = 6, baseline y = 96 — cap height 0.70 em, picked to match the ink ratio of the default font it replaced, which is why existing sizes and y positions barely shifted. A *skeleton* runs half a stroke inside that box, y = 13..89, and the standard letter spans x = 12..64 in an advance of 78. **Letterspacing lives entirely in each glyph's `adv`**: `ui.c` passes raylib a spacing of 0, so `MeasureTextEx` matches `DrawTextEx` exactly.
  - **Caps only, with lowercase aliased onto the same cells.** 24 of the 26 lowercase letters are reachable (help text, credits reel, mission descriptions, upgrade labels), so the Font carries 26 extra `GlyphInfo`/`Rectangle` entries putting the lowercase codepoint on the uppercase rec — 75 entries over 49 cells. Mixed-case copy renders uppercase, which is the arcade look, and **nothing can fall through to `?`**. Adding a character is one entry in `FONT_CHARS` plus a row in `GLYPHS`, at the same position.
  - **RGB is forced to 255 across the finished atlas, alpha untouched.** nanosvg blends premultiplied over a transparent target, so antialiased edge texels land with RGB far below 255; a tint multiply then darkens every edge — at 16px that is most of the glyph, and text reads muddy and thin — and the mipmap chain averages that dark RGB into the classic halo. Deliberately *not* ported to `svg.c`: its art is not white-only, and `SVG_LOGO` carries a baked gold gradient this would erase.
  - **The bake is one shot, not a queue.** The whole atlas is ~13ms measured, so `fontPreloadStep()` does all of it on its first call rather than adding 49 frames of wall clock to a splash whose length *is* its load time. `gameFont()` hands back `GetFontDefault()` until the atlas is resident (and permanently if the bake failed — same quiet degrade as a glyph that fails to parse), which is load-bearing rather than polite: `MeasureTextEx` measures a textureless font as zero-wide and would collapse every centered string to x = 0.
  - Like the svg glyphs, the atlas is a fixed-size texture. 128px cells cover everything up to the 80pt menu title at the worst-case `postScale()` of 4.0 — a 2.5× upscale, which a rounded stroke absorbs. **If text ever draws much larger than that, `CELL` has to grow with it.**
- **tex** (`tex.c`/`.h`) - the other half of the art pipeline: **runtime-generated textures**, built at startup from raylib's `GenImage*` family (`SUPPORT_IMAGE_GENERATION`) and therefore carrying *no source data at all* - a sky full of stars costs zero bytes of the budget. Structurally a copy of `svg.c`: `TEX_DEFS[]` table (`{gen, px, repeat}`, `STATIC_ASSERT`ed), one texture per `texPreloadStep()` call, mipmapped + trilinear, quiet degrade to drawing nothing. SPLASH drains all six calls in one update because their total measured cost is about 30ms; spacing them over six rendered frames only delayed the menu. Public surface is `texGet(id)` (for draws needing their own source rect - tiling, a jittered offset), `drawTex(id, cx, cy, w, h, rotDeg, tint)`, `texPreloadStep()` and `unloadTexCache()`.
  - **The split rule across the three art subsystems**: noise or a soft falloff → a `TexId`; a crisp authored silhouette → an `SvgId`; a letterform → a row in `font.c`; something that reshapes every frame → stays immediate-mode primitives (the rocket flame, balloon string, magnet spark). An *ellipse* stays a `DrawEllipse` — swapping it for an ellipse-shaped texture buys nothing.
  - Six textures: `TEX_PUFF` (radial falloff — every glow, halo, shadow, particle and the player trail), `TEX_CLOUD` (perlin × radial mask), `TEX_STARFIELD`, `TEX_NEBULA`, `TEX_ROCK` (cellular grain), `TEX_STATIC` (the credits snow). Three shared pixel helpers do all the work — `lumaToAlpha`, `mulAlphaLuma`, `alphaCurve` (gamma via a 256-entry LUT), the contrast knob on every generator.
  - Like the glyphs, everything is authored **white-with-alpha and tinted at draw time**, so the theme recolors it for free. `TEX_STATIC` is the one exception (opaque grey, drawn tinted `WHITE`). Gradients fade to **`WHITE_CLEAR`, never `BLANK`** — fading to `BLANK` drags RGB toward black and the mipmap chain averages RGB across transparent texels, which is the classic dark halo around a soft sprite.
  - Two shapes of trap when using them. **`TEX_ROCK` only goes over rectangular bodies** — it fills its own square box, so on an ellipse it overhangs the silhouette. And **a radial mask is a circle however much noise is inside it**: `drawCloud` stamps *three* `TEX_CLOUD` quads because the lumpy outline has to come from the arrangement, not from the texture.
  - `GenImageCellular` is distance-to-nearest-seed, so cell *centers* come out dark and boundaries bright — a web of veins. That polarity is not a bug.
  - **`GenImageWhiteNoise` quantizes its factor to whole percent.** raylib tests `GetRandomValue(0, 99) < (int)(factor * 100.0f)`, so anything under `0.01` truncates to **zero** — `0.009` is not "slightly sparser than 0.01", it is an empty image. Only 1%, 2%, 3%… exist. `STAR_THIN` (the alpha gamma) is the fine density knob instead: stars take their alpha from the perlin multiply, so a gamma above 1 deletes the ones in the perlin's dim regions and leaves the survivors sharp and 1px, thinning the field into lanes. Enlarging the on-screen tile in `drawStarfield` also thins it, but by magnifying 1px stars into bokeh.
  - **Judge these at full resolution or in-game, never off the contact strip's cell.** The strip downsamples 512px to a thumbnail, which eats 1px stars, so a starfield always looks sparser there than it is — that is exactly the mistake that shipped the night sky at 2% density and made it read as television snow.
- **post** (`post.h`/`post.c`) — post-processing. The whole frame draws into one offscreen `RenderTexture` and resolves through a single GLSL fragment shader whose source is a **string literal baked into the binary** — same no-asset-files doctrine as `svg.c`, and `LoadShaderFromMemory(NULL, src)` supplies raylib's default vertex shader. The public surface is `postBegin()` / `postScale()` / `postEnd(&fx)` / `unloadPost()`, called only from `main.c`'s loop.
  - **Effects are a per-frame mailbox, not a mode**: `PostFx` (bloom / fog / crt / vignette / crtRect) lives on `Game`, `main.c` zeroes it each frame with the always-on vignette pre-raised, and the *drawing screen* raises what it wants — `screen_play.c` sets `bloom = themeGlow()` and the fog ramp, `screen_credits.c` sets `crt` + the tube rect. Each effect is one uniform-gated branch in the shader, so an inactive one is free (a uniform branch is coherent across the whole draw). Adding an effect is one `PostFx` field + one cached uniform loc + one gated block.
  - **The target is supersampled** (`POST_SS`, 2×, dropping to 1× above `POST_SS_MAX` render width so the 1400pt Retina setting doesn't ask for a 5600² target) because it replaces the MSAA a `RenderTexture` can't have — see the Rendering model section.
  - **`GenTextureMipmaps` runs every frame in `postEnd`, unconditionally.** It is tempting to gate it on "does any effect read a mip" — that is a bug: the resolve blit itself minifies (the target is bigger than the window), so the trilinear filter samples mip 1 even with every effect off, and a stale chain shows the frame it was baked on. The chain doubles as bloom's blur (`textureLod` at mips 3/5) and fog's (mip 1.5) — no ping-pong bright-pass target.
  - **Tuning knobs are the `const float`s at the top of the shader string** (barrel, chroma, scanline/triad counts, bloom threshold and gain, fog tint) — the equivalent of `world.c`'s `#define` block. Scanline and triad counts are expressed *per tube*, not per pixel, so the CRT doesn't change density when the window resolution does.
  - **Shader uv is y-down, same as 800-space.** The resolve blit passes a *negative* source height (a framebuffer texture is bottom-up), which lands `fragTexCoord.y = 0` at the top of the window — so `postEnd` normalizes `crtRect` straight by `SCREEN_WIDTH`/`SCREEN_HEIGHT` with no flip, and any new rect-confined effect can do the same. Drop the negative height and every uv-space rect silently flips.
  - **`postScale()` is one scale for both axes**, which is only valid because the logical space is square (800×800) and every `RES_OPTIONS[]` entry in `settings.c` is square too. A non-square resolution option would have to split it into x/y (and the frame's `rlScalef` with it).
  - Two guards that look like paranoia and aren't: an empty `crtRect` zeroes `crt` in `postEnd` (the shader divides by `uRect.zw`), and a shader id equal to `rlGetShaderIdDefault()` counts as a failure, not a success (see quiet degrade below).
  - Quiet degrade: a failed framebuffer or a GLSL error (raylib hands back the *default program* — treated as failure) sets an internal flag and every entry point becomes a no-op, so the game draws straight to the backbuffer exactly as it did before post existed.
  - The credits CRT is confined to `crtRect`. A **global screen warp is skipped by decision**, not left undone: `virtualMouse()` maps raw window coords with no inverse distortion, so warping the whole frame would slide every button off its own art. Adding one means adding the inverse map there first.
- **persist** (`persist.c`/`.h`) - a tiny JSON int key-value store backing `~/Library/Application Support/Boing/save.json` (high score + settings + progress all share it). `configLoadUser` falls back to a legacy working-directory `save.json` only when the per-user file is absent, and the next `configSaveUser` migrates it to Application Support; this is required because a Finder-launched signed `.app` cannot write beside its own executable. The file is a flat `{"key": int}` object; non-int values are stored int-scaled by the caller. `configLoad(path)` parses it into a shared in-memory map once at startup (fixed `CONFIG_MAX_KEYS` = **32 slots**; a new save uses 28 and an old bundle save retaining `skinMask` / `selectedSkin` peaks at 30). Overflow is *silent*, so `progress.c` `STATIC_ASSERT`s the scalar, task-slot, upgrade, and migration peak against capacity. The parser rejects malformed or oversized input, and `configSave` writes beside the live file before atomically replacing it, so an interrupted write leaves the previous profile intact. Every subsystem shares the map, so independent saves merge instead of clobbering each other.
- **progress** (`progress.c`/`.h`) - persistent **meta-progression / coin economy**. `Progress` stores the coin bank, four cosmetic ownership masks and selected indices, `puLevel[]`, three daily progress slots, three repeatable carries, the local-date stamp, and the achievement mask. Run coins are banked at death; the same `bankRun` call advances every task and pays rewards automatically.
  - `COSMETICS[]` - four eight-item catalogs: original body colors, headwear, eyewear, and mouth-wear. Row 0 in each is the free default. Wearable positions match the player enums exactly. `cosOwned` packs seven mask bits per category; each eighth bit shares `cosEquip` with the four three-bit selections and a format marker. Legacy `skinMask` / `selectedSkin` keys do not carry over by product decision, so an old save starts cosmetics fresh while preserving coins, achievements, and upgrades.
  - `PU_UPGRADES[PU_UPGRADE_COUNT]` - `{label, base}` per upgrade **track**, `cost(level) = base*(level+1)` via `upgCost`. The `PuTrack` enum is the 12 tracks: Magnet/Rocket/Balloon each Spawn/Effect/Duration, Shield Spawn/Effect only, plus one shared `PU_DEBUFF_SUPPRESS`. `MAX_UPG_LEVEL` = 5 buyable levels each, stored in `puLevel[]`.
  - Mission data is split into `DAILY_TASK_POOL[]`, `REPEATABLE_TASKS[]`, and `ACHIEVEMENTS[]`. A local `YYYYMMDD` stamp deterministically shuffles three unique daily rows without touching gameplay RNG; a date change clears only those three progress slots. Daily tasks cap and pay once that day. Repeatables pay once per crossed threshold and preserve overflow. Achievements keep the original one-run comparisons and one-time rewards; the persisted key remains `missionMask` so existing completions migrate.

  Query helpers: `dailyTask`, `progressRefreshDaily`, `achievementDone`, `cosmeticOwned`, `progressCharacter`, `upgLevel`, `tryBuy`, and `bankRun`. `loadProgress` clamps all values at the user-editable save boundary. Coin-bank additions saturate at `INT_MAX` rather than overflowing.

## Robustness convention

Every enum-indexed lookup table carries a `STATIC_ASSERT` tying its size to the enum, so a dropped or added row fails the build instead of silently producing a NULL handler, a zero duration (divide-by-zero), or an out-of-range read: `STATES[]`, `POWERUP_DEFS[]`, `PU_UPGRADES[]`, `COSMETICS[]` and its four item tables, `REPEATABLE_TASKS[]`, `MISSION_TAB_LABELS[]`, `TRACKS[]`, `PRELOAD_ORDER[]`, `sfxLen[]`, `ERA_STINGER_PITCH[]`, `ROW_LABELS[]`, `THEMES[]`, `ERA_NAMES[]`, `GLOW[]`, `SVG_DEFS[]`, `TEX_DEFS[]`, `ICON_SVG[]`, `HAT_SVG[]`, `GLS_SVG[]`, `MOUTH_SVG[]`, `TETRO[]`, `GLYPHS[]` (tied to `FONT_CHARS`'s length rather than an enum - same idea, and the pair must stay in the same order), plus the theme-to-level-track count and `offsetof(Theme, backdrop)` alignment checks. Keep this up when adding a table.

A second, smaller family of guards covers **capacity** rather than completeness: the packed cosmetic save layout is fixed at four categories with eight rows each; achievements are capped at 31 because `achievementMask` uses `1 << i`; the daily pool must fill all three slots; and progress's fixed plus two possible legacy keys and all `pu%d` keys must fit `CONFIG_MAX_KEYS`. These are the places where a new row could silently stop persisting instead of crashing.

**The tables must be unsized and positional, or the assert is a decoration.** `static const T FOO[FOO_COUNT] = {...}` is `FOO_COUNT` long whatever rows you put in it, so the count check compares `FOO_COUNT` to itself. Designated rows have a second trap: removing a middle row leaves a zero-filled hole without shortening the array. Every completeness-guarded table here is therefore unsized and positional in exact enum order, so dropping any row changes its measured length.

A sized `extern` declaration in a header is enough to break this even when the definition looks unsized: the definition picks up the declaration's length as its composite type and `sizeof` measures the header. `POWERUP_DEFS`, `PU_UPGRADES`, and `REPEATABLE_TASKS` are declared `[]` for this reason. Field designators inside a positional struct row are fine; it is the table-row index designator that hides holes.

When you add a guard, mutate the table and watch the build break before you trust it — three of these asserts sat un-fireable for months precisely because nobody did.
